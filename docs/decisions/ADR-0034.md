# ADR-0034: Default-Editor Registration Stays A `.reg` Handoff, Never A `winreg` Dependency

**Status:** Accepted
**Date:** 2026-08-21

## Context

ADR-0012 decided that this product registers through OS-supported mechanisms
and never patches another editor. It did not decide *how* the Windows half
writes its own registration -- and by the time `bp-platform` and
`default_editor.rs` shipped, that question had an answer in the code without
ever being asked as one. `bp-platform` generates the correct
`HKCU\Software\Classes` shape, renders it as a `.reg` script, and stops:
writing the keys directly would mean the `winreg` crate or `unsafe` Win32,
both of which the crate forbids. The shell hands the user that file and opens
`ms-settings:defaultapps` for them to finish the association themselves.

That is a real architectural choice -- take a Windows-only dependency and
narrow `bp-platform`'s no-`unsafe` guarantee for the sake of one fewer click,
or keep the crate as it is and cost the user two -- and it had been living as
an implementation detail rather than a decision anyone could point to. D8
existed because "it should be decided, not defaulted into".

## Decision

**The `.reg` handoff is correct, and it stays.** `bp-platform` never takes
`winreg` or `unsafe` Win32 to write these keys; File ▸ Set as Default Editor
generates the file, the user places it, double-clicks it, and
`ms-settings:defaultapps` is opened for the follow-through. This is not a
placeholder for a more direct implementation later -- it is confirmed as the
answer.

ADR-0012 already argued the user keeps control of this choice, and a `.reg`
file the user actively runs is a stronger form of that than a background
write ever would be: nothing changes on their machine that they did not see
and choose to apply. Two clicks against one is a small cost for keeping
`bp-platform`'s `#![forbid(unsafe_code)]` whole and this crate free of a
platform-specific dependency every other crate in the workspace is written
without.

## Consequences

- D8 leaves `project/DECISIONS_NEEDED.md`.
- No code changes. `crates/bp-platform/src/editor.rs` and
  `crates/bp-ui/src/default_editor.rs` already implement exactly this, and
  their existing tests -- including the one asserting the notice names
  `ms-settings:defaultapps` -- stand as this ADR's regression coverage.
- `winreg` and any Win32 registry-writing dependency are now a closed
  question for this capability, not an open one a future session might
  reopen for convenience. Revisiting it needs a new ADR, the same as
  reversing any other one here.
