# ADR-0065: Two Things The Reduction Weakened, Repaired

**Status:** Accepted
**Date:** 2026-08-30
**Amends:** [ADR-0062](ADR-0062.md), [ADR-0064](ADR-0064.md), [ADR-0020](ADR-0020.md)

## Context

[ADR-0059](ADR-0059.md)'s five removals are done. Three things came out of
them materially weaker, and they were reported as consequences rather than as
defects because that is what they were: each was a real cost of a decision
taken deliberately.

**One of the three is accepted and stays accepted.** Trap 7's upgrade coverage
fell from four files to three and [ADR-0050](ADR-0050.md)'s golden envelope
vectors are gone. There is no format left for them to be about, so nothing can
restore them, and pretending otherwise would be worse than the gap.

**The other two are repaired here**, and neither repair reverses a removal.

## Decision 1: `sniff` gets something that can contradict it again

[ADR-0062](ADR-0062.md) removed `bp-data` and, with it, the cross-crate test
asserting that whatever `sniff` called a document, the parser that then
handled it agreed. That ADR's own lesson was the problem:

> Removing a caller does not only remove work. It can remove the only thing
> that could contradict a claim.

**`tests/integration/tests/sniffing_agrees_with_a_parser.rs` restores the
claim**, over JSON and JSON Lines — which is precisely where the defect the
original test caught lived. `sniff` counted lines beginning with `{`, called
two or more of them JSON Lines, and so classified a pretty-printed array of
objects as a format its own parser would reject.

**It costs no dependency.** `serde_json` is already a workspace dependency and
was already a dev-dependency of `tests/integration`, so nothing is added to
the shipped binary and nothing new enters the graph. **The Data menu is not
coming back**: what was worth keeping was never the menu, it was the
contradiction.

### What it does not claim

`sniff` reads a prefix and guesses, and is not validation. "This text starts
with `{` and is not JSON" is not a defect — `Format::Json` is the right guess
for a malformed JSON file, and the user gets a syntax profile rather than an
error. The falsifiable claim is the narrower one that actually broke: **for a
document that *is* valid JSON, `sniff` must not classify it as something a
parser then refuses.**

Four tests: the three original fixtures kept verbatim as a record of the
defect, the JSON Lines direction (a rule tightened until it never says
`JsonLines` would pass the first three and be useless), the one-line boundary,
and a proptest over generated JSON serialised both compact and pretty.

**Watched failing before it was called done.** The old line-counting rule was
temporarily restored in `bp-formats`; the fixture test *and* the generated
property both failed, then both passed with the rule put back. A guard nobody
has seen fail is a guard nobody knows the shape of.

## Decision 2: Private keeps a recovery journal

[ADR-0064](ADR-0064.md) set Private and Confidential to `Recovery::Disabled`
when the sealed journal went, on [ADR-0020](ADR-0020.md)'s rule that a control
which quietly weakens itself is worse than an absent one.

**The word carrying that rule is *quietly*, and this menu has never been
quiet.** The Privacy menu prints what the journal actually is, on a row of its
own: "Recovery journal: on, unencrypted". A user under Private is told, before
anything happens, exactly what is on their disk.

So Private becomes `Recovery::Plaintext`. **Confidential and Maximum stay
`Disabled`**, and the line between them is the decision:

- **Private stops content leaving the machine.** A journal on the local disk
  does not contradict that. Losing a session's unsaved work to protect against
  an attacker who already has the disk is the wrong trade.
- **Confidential records nothing about the document**, and a recovery journal
  is a copy of unsaved work sitting outside the file. That is where "no
  journal" belongs, because it is the profile whose whole subject is what
  touches the disk.

Monotonicity holds: `Plaintext ≤ Plaintext < Disabled ≤ Disabled`.

### The readout is load-bearing, and a test says so

`the_recovery_row_says_unencrypted_where_the_journal_is_unencrypted` is not
decoration. It is the licence for this change: **if the readout ever stops
naming the journal's actual form, Private must go back to `Disabled`**, and
the test comment says that in as many words so the next person to touch the
menu finds out from the code rather than from this file.

## Consequences

**ADR-0064's "only Standard gets crash recovery" is superseded within a day of
being written**, and that is worth being plain about rather than quietly
correcting. The decision it made was defensible on its own terms; what it
under-weighted was that its own menu already told the truth, so the failure
ADR-0020 forbids — a user believing a control is on when it is not — could not
occur. **A rule with a qualifier in it should be read with the qualifier**,
and "quietly" was doing more work than it got credit for.

**`README.md`, `specs.md` and `MENU_MAP.md` all said "only Standard".** They
say the line is between Private and Confidential now.

**Neither repair re-adds a capability.** No crate returns, no menu row
returns, no dependency is added, and the line count moves by the size of one
test file. The reduction stands; two of its costs did not have to be paid.

## The lesson

> **A consequence recorded honestly is still worth re-reading once the change
> that produced it has landed.**

Both of these were written down as costs in the ADRs that caused them — that
is why they were reportable at all, and why fixing them took an afternoon
rather than a rediscovery. But *recording* a cost is not the same as
*accepting* it, and the sequence had enough momentum that both went into the
record as settled when only one of them was.

The habit worth keeping: when a removal reports a consequence, ask separately
whether it is **inherent** to the removal or merely **concurrent** with it.
The golden vectors were inherent — no format, no vector. The other two were
concurrent: a test does not need a menu, and a journal does not need
cryptography to be honestly labelled.
