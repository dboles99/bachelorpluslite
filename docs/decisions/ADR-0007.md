# ADR-0007: Full Performance and File-Safety Feature Set

**Status:** Accepted
**Date:** 2026-08-16

## Context

specs.md sections 5 and 6 call for rope buffers, memory mapping, huge-file
mode, parallel processing, atomic save, file watching, recovery journals and
structural undo. These are cross-cutting: retrofitting them onto a naive
buffer and a naive save path is substantially harder than starting with them.

## Decision

Adopt the full set as a v1 requirement rather than a later optimisation.
Saving is atomic from the first implementation: write a temporary file in the
target's directory, flush it to the device, optionally read it back, then
rename over the target.

## Consequences

- A save either fully succeeds or leaves the previous file untouched. There
  is no window in which the user's file is half-written.
- Read-back verification costs roughly double the I/O of a save and is on by
  default, because only it distinguishes "the OS accepted the bytes" from
  "the bytes are on disk", and the status bar claims the latter.
- Implemented in `crates/bp-files`.
