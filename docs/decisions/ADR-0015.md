# ADR-0015: UI Toolkit

**Status:** Accepted
**Date:** 2026-08-17

## Context

`PROJECT_MEMORY.md` names Slint as the leading candidate but requires that the
toolkit be benchmarked and prototyped before an irreversible commitment. The
toolkit choice constrains ADR-0009 (data-driven themes must restyle every
surface) and is measured against specs.md section 22.

The same shell -- menu bar, tab strip, gutter, live editable buffer, two-line
status bar, four themes -- was built twice and measured under identical
release profiles. Full report:
`artifacts/ui/ui-toolkit-spike-17AUG2026.md`.

| Metric | Slint 1.17 | egui/eframe 0.36 |
| --- | ---: | ---: |
| Time to window | 98 ms | 197 ms |
| `main()` → first frame | 442 ms | 878 ms |
| Idle working set | 64.4 MB | 153.8 MB |
| Idle private bytes | 70.8 MB | 359.8 MB |
| Release binary | 10.4 MB | 12.2 MB |

## Decision

Adopt **Slint** as the UI toolkit for BachelorPad+.

## Rationale

- Roughly 2× faster to a window and 2.5× lighter on idle working set, on
  every run, on the metrics the product is specified against. Private bytes
  differ by 5×.
- Theming fits ADR-0009: a `global Palette` of properties supplied from Rust
  restyles every surface including text input, so `bp-ui/ui/app.slint`
  contains no colour literals and a user theme uses the same mechanism the
  built-ins do. egui's `Visuals` is a fixed set of toolkit-defined slots; the
  four themes fit, but fully custom surfaces would mean painting them by hand.
- API stability. egui 0.36 broke four separate APIs used by a shell this small
  (`App::update` removed in favour of a required `App::ui`, panels moved to
  `&mut Ui`, `TopBottomPanel` folded into `Panel`, `TextEdit::frame` retyped)
  and ships breaking releases roughly quarterly. Slint has held a stable 1.x
  API since 1.0. For a product of this scope, toolkit churn is a recurring tax.

egui is the better prototyping experience and the right choice where UI
iteration speed dominates. That is not this product's constraint.

## Consequences

- `bp-ui` depends on Slint; `.slint` markup is compiled by a build script, so
  layout lives in a second language and the build has a codegen step.
- `#![forbid(unsafe_code)]` is not usable in `bp-ui`. Slint generates the
  window's item tree into the crate and that code needs `unsafe` with a local
  `allow`, which `forbid` cannot permit. The crate uses `deny` instead, which
  still rejects hand-written `unsafe`.
- Linux is confirmed working: the shell builds, links and runs there, verified
  under WSLg after installing `libxkbcommon-x11`. Comparative *timing* on
  Linux remains unmeasured, because WSLg's compositor makes startup numbers
  unrepresentative of a native desktop. The decision rests on Windows
  measurements plus Linux viability.
- The egui spike has been deleted, and the Slint spike with it: the shell now
  lives in `bp-ui`, and the startup instrumentation moved into the real
  application (`--measure-exit`). A benchmark fixture measures the fixture and
  drifts from the product. The archived measurements remain in
  `artifacts/benchmarks/`.
- Renderer selection and the startup targets are settled separately in
  ADR-0017.
