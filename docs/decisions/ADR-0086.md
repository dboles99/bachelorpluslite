# ADR-0086: The Release Candidate Ships Unsigned, And 1.0 Is Signed Through SignPath Or The Store

**Status:** Accepted, amended 2026-10-01 by [ADR-0094](ADR-0094.md) -- 1.0.0
ships unsigned, and signing moves to a 1.x release by the same routes
**Date:** 2026-09-25
**Answers:** D24
**Amends:** [ADR-0055](ADR-0055.md), [ADR-0067](ADR-0067.md)

## Context

[ADR-0055](ADR-0055.md) deferred code signing and laid out the choice as
three rows: an OV certificate, whose SmartScreen reputation accrues over
downloads; an EV certificate, which buys that reputation *immediately*; and
self-signing, refused. [ADR-0067](ADR-0067.md) declined an installer and put
winget out of reach because *"this repository is private and there are no
published release artefacts."*

**Both premises are false now, and one was false when it was written.**

- **EV no longer buys reputation.** Microsoft removed the EV bypass in 2024.
  EV-signed files now build SmartScreen reputation over time exactly as OV
  ones do, and Microsoft's own guidance says paying the EV premium to avoid
  the warning *"is no longer justified"*. ADR-0055 was written in August
  2026, so its EV row was already out of date -- the third accepted ADR found
  resting on a false external fact, after ADR-0016 and ADR-0048.
  Test: *Code signing options for Windows app developers*, Microsoft Learn,
  `learn.microsoft.com/windows/apps/package-and-deploy/code-signing-options`,
  section *EV certificates -- no longer recommended for SmartScreen*.
- **The repository has been public since 2026-09-10**, with a release
  pipeline in hosted CI ([ADR-0073](ADR-0073.md)).
- **And winget accepts a portable archive.** A manifest can declare
  `InstallerType: zip` with `NestedInstallerType: portable`, so the ZIP this
  project already builds is installable by winget with no installer written.
  Test: `grep -rl 'NestedInstallerType: portable' manifests/` in a clone of
  `microsoft/winget-pkgs`.

What is left on the table:

| Route | Cost | SmartScreen | Who can have it |
| --- | --- | --- | --- |
| **SignPath Foundation** | Free | Reputation builds over time | Open-source projects with a public build pipeline, on application |
| **Microsoft Store** (MSIX) | Free | **No warning** -- the Store re-signs | Anyone; needs an MSIX package and certification |
| **Azure Artifact Signing** | ~$10 a month | Builds over time | Organisations in listed regions; **individuals in the USA or Canada only** |
| OV certificate | $150--300 a year, plus a hardware token | Builds over time | Anyone |
| EV certificate | $400+ a year | **Same as OV since 2024** | Anyone |

## Decision

1. **The release candidate ships unsigned**, with the SmartScreen and Smart
   App Control behaviour documented where a user will read it before they
   download, as the installation page already does.
2. **The 1.0 route is SignPath Foundation**, applied for now, because it has
   weeks of lead time and costs nothing. The application is Daniel's to make.
3. **The Microsoft Store is the parallel second route**, and the only one that
   removes the warning outright rather than starting a reputation clock.
4. **EV is off the table.** It was the expensive row, and the one thing it
   bought no longer exists.
5. **winget is open**, and becomes a 1.0 distribution task rather than a
   blocked one. It no longer needs an installer, and a signature is what
   makes it worth doing, so it follows the signing route.

## Consequences

**Every signature now starts a reputation clock**, including SignPath's.
Signing is still worth having -- it names a publisher, and it lets reputation
carry from one release to the next instead of every new hash starting from
nothing -- but no route except the Store makes the first download silent.

**Money and applications are Daniel's.** This ADR decides the route; it does
not spend anything.
