# ADR-0069: The Registration Table Stops Offering A Format This Product Cannot Open

**Status:** Accepted
**Date:** 2026-08-30
**Amends:** [ADR-0012](ADR-0012.md), [ADR-0021](ADR-0021.md)
**Depends on:** [ADR-0064](ADR-0064.md)

## Context

[ADR-0064](ADR-0064.md) removed encryption, and with it the ability to open a
`.bpadx` -- an encrypted envelope whose plaintext was detected only *after*
decryption. It said so, and it deliberately left the registration table alone:
what this product claims to open is a different question from what it can
decrypt, and ADR-0064 declined to answer a question it had not asked.

**That question came due the moment a user reached for File ▸ Set as Default
Editor**, which is the one place the table stops being a table and becomes a
promise made to the operating system.

## What was actually there

`.bpadx` was in `TypeGroup::Own`, and **every preset claimed that group** --
including the one named *Notepad Replacement*, which exists precisely so a
user can take the smallest sensible bite.

So the mildest available choice registered a file type that, double-clicked,
would open this editor onto a window of ciphertext. Not an error, not a
refusal: a document. **That is worse than Windows saying it cannot open the
file**, because the failure arrives dressed as success, and it arrives in
Explorer rather than in the product.

A test knew and said nothing. `every_registerable_extension_is_one_bp_formats_can_identify`
is the one agreement between the registration table and the parser, and it
carried an exemption:

```rust
fn must_be_parseable(file_type: &FileType) -> bool {
    file_type.group != TypeGroup::Own
}
```

The exemption was correct when written -- `.bpadx` was genuinely unparseable
and genuinely openable, and those two facts were the whole reason for the
group. ADR-0064 falsified the second and left the first, and **an exemption
does not notice that the reason for it has gone.** It is trap 4 with a
`filter` in place of a comment: two claims about the same table, coexisting
because nothing asked them together.

## Decision

**`.bpadx` leaves `FILE_TYPES`, `TypeGroup::Own` leaves the enum, and the
exemption leaves the test.**

All three, and the third is the point. Removing the row while keeping the
exemption would leave the next product-owned format free to be unopenable
again, silently, on the same grounds. The test now reads:

```rust
// No exemption: ADR-0069 removed the one type that had one.
for file_type in FILE_TYPES {
```

**Every extension this product offers to register for is one it can open.**
That is a sentence the test now proves, and could not have proved yesterday.

### `TypeGroup::Own` goes rather than staying empty

The first draft kept the variant, with a comment arguing that the *question*
it answers outlives the one format that answered it. That comment was wrong in
the way this session has now recorded three times:

> A type with no producer is not an implementation. It is a claim.

An enum variant no table row uses is a claim that this product owns a file
format. It does not. If it owns one again, the variant and its exemption come
back **together**, which is the pairing that failed here -- and three lines is
not a cost worth buying an untrue statement with.

### The MIME package survives, and the reason is worth recording

The obvious next inference is that `desktop::mime_package` is now dead:
`.bpadx` was the product's own type, so a package defining the product's own
types has nothing to define.

**It is not dead, and the inference was wrong because the function's name was
imprecise.** `is_own_mime_type` also answered true for `text/x-powershell` --
not a type this product invented, but one `shared-mime-info` does not define,
so it has to be defined by whoever wants to associate with it. That is a
different property wearing the same word, and the function is now named for
what it tests:

> Whether this type is one the shared MIME database does not already know, and
> so must be defined rather than referred to.

The Linux MIME package still ships, still defines exactly one type, and still
gives the three PowerShell extensions one element with three globs.

## Consequences

**Registration on both platforms claims less, and claims nothing false.** The
Linux `.desktop` entry's `MimeType=` list now begins at `text/plain`, and the
Windows `.reg` handoff no longer offers a ProgId for an extension whose
handler would show ciphertext.

**A user who registered `.bpadx` under an earlier build still has that
association**, and this product will not take it back -- [ADR-0012](ADR-0012.md)
forbids seizing associations and says nothing about un-seizing them, which is
the same act pointed the other way. It is inert: the ProgId names an executable
that opens the file as text. Nothing is deleted from anyone's registry on their
behalf.

**`.bpadx` files a user already has are unaffected and unreadable**, which
ADR-0064 established. This ADR does not change that; it stops the product
advertising otherwise.

## The lesson

> **An exemption outlives the reason for it, because an exemption is a
> `filter`, and a `filter` cannot notice.**

Every trap this repository has recorded about comments -- a claim is not a
property, two claims coexist until something asks -- applies at full strength
to a test's own escape hatches, and applies *worse*, because an exemption sits
inside the mechanism that is supposed to be doing the asking. A stale comment
is read by a person who may doubt it. A stale `filter` is read by nothing.

**When a decision removes a capability, search the tests for what stopped
being checked**, not only the code for what stopped being called. The `grep`
that finds a producerless type finds a reasonless exemption too, and it is the
same `grep`: *who produces this, and who reads it?*
