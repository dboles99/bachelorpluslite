# ADR-0057: Executing Anything Is Removed, And With It Notebooks

**Status:** Accepted
**Date:** 2026-08-29
**Supersedes:** [ADR-0038](ADR-0038.md), [ADR-0040](ADR-0040.md), [ADR-0043](ADR-0043.md), [ADR-0045](ADR-0045.md)
**Amends:** [ADR-0011](ADR-0011.md), [ADR-0025](ADR-0025.md), [ADR-0048](ADR-0048.md)

## Context

BachelorPlusLite is a clone of BachelorPad+ being reduced to the feature set
of Windows 11 Notepad, plus a note-organising layer that survives on purpose.
Windows Notepad runs nothing. Neither, now, does this.

This is the first capability to leave, and it was chosen first because it is
the least entangled: `bp-notebook` and `bp-execution` each depend on no other
crate in the workspace, and — the comment in `crates/bp-ui/Cargo.toml` said so
before this change removed it — **neither depended on the other, deliberately.**
The single place the two were both visible was `bp-ui/src/state/notebook.rs`,
which mapped eight cell kinds onto three languages. Delete that file and the
two crates have nothing left holding them in.

They came out together rather than one at a time for that same reason. Removing
`bp-execution` alone would have left a notebook module that could list cells
and not run them, which is a half-feature, and `project/WORK_QUEUE.md` warns
about exactly that shape.


> **Amended 2026-09-25 ([ADR-0084](ADR-0084.md)).** There is one program this
> product can start, and it is a dependency's rather than its own: on Linux,
> `rfd`'s file pickers fall back to `zenity` when no XDG desktop portal
> answers. If that fails too, the picker returns nothing and no data is at
> risk. The message dialogs, which ran `zenity` unconditionally, are drawn in
> the window now (W1-02).

## Decision

**Remove the ability to execute anything, and remove notebooks with it.**

Deleted: the `bp-execution` and `bp-notebook` crates, `bp-ui`'s
`state/notebook.rs` and `ui/run_panel.slint`, the Run and Notebook menus, the
`RUN_CELL_BASE` action-id window, the integration test
`notebooks_through_files.rs`, and the notebook fuzz target and its corpus.

Kept: `.ipynb` as a *recognised file type*. `bp-formats` still identifies one
and `bp-platform` still offers to register for it. A Jupyter notebook is JSON,
JSON is text, and a text editor that opens it is not making a claim it cannot
keep. Both crates are themselves scheduled for removal, and the question of
whether `.ipynb` should stay registerable belongs to that change rather than
this one.

## Consequences

**Two recorded decisions stop being about anything, and one gets stronger.**

[ADR-0025](ADR-0025.md) chose namespaced `.ipynb` metadata and a `UserGesture`
no parsed file can produce. [ADR-0011](ADR-0011.md) and specs.md section 15
required that notebook content never auto-runs. Those were good decisions and
the mechanism worked: `UserGesture::from_user_command()` was called in exactly
one place in the entire shell. The constraint is now vacuous rather than
enforced — nothing auto-runs because nothing runs — and a constraint that
cannot fail is worth recording as removed rather than leaving to read as live.

**The dangerous-consent surface is gone, not merely unused.** R011's trap 9
names a defect that shipped here once: a signing passphrase typed into the open
document, because a menu row took the keyboard focus. The Run panel was one of
the surfaces that shape applied to. Deleting it removes the hazard's home
rather than leaving it correct-for-now.

**The action-id window above 800 is free.** `RUN_CELL_BASE` held a bounded
200-wide range, and its bounding test went with it. `no_two_range_dispatch_windows_overlap`
stays and still means something for the windows that remain; that test is the
one guarding trap 1, and it was deliberately not deleted alongside the feature
it happened to cover.

**One comment in a kept crate had borrowed its reason from a deleted one.**
`bp-semantic::is_fence` recognises both fence characters, and said it did so
"because `bp-notebook` reads both". The rule is unchanged and still right; its
justification had to be restated in terms that survive, because a comment whose
reason names a crate that no longer exists is trap 3 in its purest form — a
claim nothing would fail to disprove.
