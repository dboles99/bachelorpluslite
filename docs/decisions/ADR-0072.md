# ADR-0072: macOS Is Declined, And What It Would Cost Is Written Down

**Status:** Accepted
**Date:** 2026-09-10
**Depends on:** [ADR-0001](ADR-0001.md), [ADR-0055](ADR-0055.md)

## Context

The public release was asked for on Windows, Linux **and macOS**. ADR-0001
names two targets and has since the first commit, so this was a request to
widen the platform matrix rather than to build something that already exists.

Standing authority 3 says a planned row that cannot be kept is removed with
the reasoning written down. This is the same act pointed forwards: a row that
does not exist yet, declined before it is written, for reasons worth more than
the row would have been.

## What a macOS build would actually be

**It would compile today, and that is the problem.** `bp-platform` consults
the compile target in exactly one place:

```rust
#[cfg(windows)]
pub const HOST: Platform = Platform::Windows;
#[cfg(not(windows))]
pub const HOST: Platform = Platform::Linux;
```

The doc comment beside it is explicit that a target which is neither Windows
nor Linux is reported as Linux, because of the two, the Unix-family answer is
the one that will not silently produce a backslash-separated path. That was
the right call for a target nobody builds. It is the wrong answer to ship:

- **Configuration, data, cache and state** would resolve to `~/.config` and
  `~/.local/share`. macOS puts them under `~/Library/Application Support`.
- **File > Set as Default Editor** would write a `.desktop` entry and a MIME
  package into a home directory where nothing reads either. Not a missing
  feature -- a feature that reports success and has done nothing.

So a macOS build is not a build. It is a third `Platform` variant, a third
column in `dirs`, a registration path built on Launch Services and UTI
declarations in an `Info.plist`, an `.app` bundle and a `.dmg`. Every rule in
`paths` would need its macOS answer decided rather than inherited.

## And it would arrive quarantined

[ADR-0055](ADR-0055.md) deferred code signing and refused self-signing
outright. On Windows that costs a SmartScreen warning the user can click past,
and `New-Release.ps1` says so in the same words on every run.

**On macOS an unsigned, un-notarised `.app` does not open.** Gatekeeper
refuses it, and the way past is right-click-Open or stripping
`com.apple.quarantine` by hand. The only real fix is the Apple Developer
Program at $99 a year, plus `codesign` and `notarytool` in CI with secrets
behind them.

So the honest version of *ship macOS too* is: design a third platform,
implement it against an operating system with no machine here to test it on,
buy a certificate, and reverse ADR-0055 for one target.

## Decision

**macOS is not a target. Windows 10, Windows 11 and Linux, exactly as
ADR-0001 has always said.** The website says *Windows and Linux* rather than
staying quiet about it.

`Platform::HOST` keeps its current fallback and its current doc comment. The
comment is now *more* true than when it was written, because this ADR is what
it points at.

## What would change the answer

Recorded so that revisiting this is a decision rather than a rediscovery:

1. **A Mac to test on.** Nothing else on this list matters without it. Every
   verification claim about macOS would otherwise be a claim about a CI runner
   nobody has looked at, which is trap 7 with a different operating system in
   it.
2. **An Apple Developer membership**, because an editor a user cannot open is
   not a release.
3. **Somebody asking.** Windows and Linux are where this product's users are,
   and a third platform is cheapest to add once there is a person waiting for
   it.

## Consequences

**The website and `README.md` say Windows and Linux, and say it in the
positive** -- naming what runs, rather than leaving a visitor to infer it from
a list of two downloads.

**Hosted CI is configured for two targets, not three**
([ADR-0073](ADR-0073.md)), which keeps the release workflow the same shape as
the local gate. Adding a macOS runner later is one matrix entry and the whole
of the work above.

**No macOS code is written speculatively.** A `Platform::MacOs` variant with
no implementation behind it is a compile unit and a merge surface, which is
the argument the workspace manifest already makes about empty crates.

## The lesson

> **The dangerous unsupported platform is not the one that fails to compile.
> It is the one that compiles and answers as something else.**

A target that refuses to build announces itself. This one would have produced
a working editor that put its files in the wrong place and reported a
successful file-type registration that had done nothing -- and both of those
are findable only by somebody sitting at a Mac.

`Platform::HOST`'s fallback is right for a target nobody ships and wrong the
instant one is shipped, and nothing in the code marks that boundary. **This
ADR is the marker**, which is why declining costs an ADR rather than a
sentence.
