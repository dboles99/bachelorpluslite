# ADR-0047: An Agent Gets Standing Authorities, One Home Per Fact, And A Gate That Checks Before It Repeats

**Status:** Accepted
**Date:** 2026-08-22

## Context

Ten build sessions in, this repository's record is unusually good and its
process is unusually slow. Those two facts have the same cause.

Measured at the end of the tenth session, before this ADR:

| | |
| --- | --- |
| Standing record | **27,568 words** across nine files, plus 46 ADRs |
| Required reading before touching anything | **~12,250 words** |
| Copies of the lesson "undecided reads like large" | 4 (`README`, `ROADMAP`, `DECISIONS`, `NEXT_SESSION`) |
| Windows gate executions per commit | **3** — the explicit full run, pre-commit, pre-push |
| Share of a session spent on the record rather than the code | roughly 60% |

None of that is waste in the ordinary sense. The record is *why* this project
has caught what it has caught — five defects found by driving the window, four
traps named before they were sprung a fourth time. The problem is narrower:
**the same fact is written in four places and read from four places**, and the
gate runs three times because nothing can tell that it already ran.

There was also a subtler cost, and it is the one that motivated the authority
half of this decision. A session would stop and ask permission for things the
record already said were correct — whether to take the ready item, whether to
commit after a green gate. Each stop is a round trip measured in hours of
wall-clock, and every one of them was answered by a rule that already existed
but had never been written as a *permission*.

## Decision

### 1. `CLAUDE.md` exists, and it is short

There was no entry point. The conventions were real and were spread across
`NEXT_SESSION.md`, `WORK_QUEUE.md` and `R011`, to be discovered by reading.
`CLAUDE.md` now holds what you need *before* you touch anything and links out
for the rest. **It is capped at about a screen and a half by intent** — an
entry point that grows into another document to read has become the problem it
was written to solve.

### 2. Three standing authorities, granted once

- **Take the top ready item and finish it.** Do not ask which, or whether.
- **Commit and push once the full gate is green on both legs.** Not merging to
  `main` (that is D13), and not rewriting pushed history.
- **Delete or rename a planned feature, with an ADR**, when it would promise
  something the product cannot keep.

The third is the one worth defending. It is the most consequential thing an
agent has done here — [ADR-0044](ADR-0044.md) removed DOI Lookup,
[ADR-0046](ADR-0046.md) removed or rewrote five rows — and both times it
needed explicit per-item permission first. **The ADR is the deliverable**, and
requiring permission to write one means the decision does not get made.

### 3. A session opens by *asking*, not by reading

`project/DECISIONS_NEEDED.md` gets a batch section written to be pasted
verbatim, and `CLAUDE.md` makes asking it the first act of a session — then
work proceeds without waiting for the answer.

The file's own rule already said to ask everything in one batch. It never
happened, because a session opens by reading, and by the time it has read
enough to ask well it has also found enough to start. **D13 has waited five
sessions for want of being asked, not for want of an answer.**

### 4. One home per kind of fact

`CLAUDE.md` carries the ownership table. The rule that does the work:
**link, do not restate.** Applied immediately:

- `README.md`'s "Recently closed" (3,586 words, two thirds of the file, all of
  it lessons) moved to `DECISIONS.md`. README keeps twelve one-line facts.
  **5,519 → 2,138 words.**
- `WORK_QUEUE.md`'s Tiers 0.5, 1 and 2 (631 words, all lessons, no work) moved
  to `DECISIONS.md`, leaving three headline bullets.
- `WORK_QUEUE.md`'s manual-pass argument, which `NEXT_SESSION.md` §3 owns,
  became a pointer.
- `ROADMAP.md` keeps the phase facts and names the lesson without retelling it.

**The total word count barely moved, and that is the honest result** —
27,568 to 27,800, because nothing was deleted and `CLAUDE.md` was added. What
moved is *required reading at session start*: **~12,250 → ~7,956 words**, with
the entry point at 1,368 instead of 5,519. The durable win is not size, it is
that a fact now has one place to be corrected.

### 5. The gate checks before it repeats

pre-push no longer re-runs the whole Windows gate unconditionally. It asks
`scripts/Test-GateEvidence.ps1` whether a full gate — **including a Linux leg
that actually ran** — has already passed over exactly this content, and skips
only when the answer is yes.

`Invoke-LocalCI.ps1` now records evidence automatically after a successful
full run, stamped with `source_at`: the newest write time of any *tracked*
file, taken after the stages finish. That dates the **content**, not the
commit, which is the only thing that can work — the gate runs on a working
tree, and the commit that tree becomes does not exist yet. Edit anything and
the record is stale by construction.

**It fails closed.** No record, an unreadable one, a stale one, a record whose
Linux leg skipped, or a git command that will not answer — every one of those
runs the full gate. A verification that fails open silently disables the thing
it protects.

What this proves is weaker than a content hash and is stated as such: not that
the pushed tree matches the gated one byte for byte, but that **nothing
tracked has been written since**.

### 6. `cargo-nextest`, with the doctest trap named

Measured on this workspace, warm:

| | |
| --- | --- |
| `cargo test --workspace` | **111.8s** |
| `cargo nextest run --workspace` | 35.4s |
| `cargo test --workspace --doc` | 9.8s |
| **nextest + doctests** | **45.2s** |

About 2.5x, roughly 67s per leg and 134s per full gate.

**The trap is that nextest cannot run doctests at all, and this workspace has
six that matter.** Five are `compile_fail` proving a `UserGesture` cannot be
constructed outside the crate that defines it — which *is*
[ADR-0011](ADR-0011.md) and [ADR-0025](ADR-0025.md)'s "notebook content never
auto-runs", enforced by the type system and checked nowhere else. Swapping the
runner without adding a `--doc` stage would have retired that guarantee in
silence.

An early measurement suggested no gain at all (73s for doctests) and was
wrong: that run was cold, and rustdoc was building every crate's docs for the
first time. **A benchmark taken once is a benchmark of the cache.**

Not a required tool. A clone without it runs `cargo test --workspace`, which
covers both halves more slowly. Both legs decide independently, because the
host and the WSL distro install tools separately.

### 7. Items are sized against the cost of entering the repository

`WORK_QUEUE.md` used to say each item was the smallest thing worth doing and
should be taken whole. Still true, and the advice built on it stopped being
right: **learning enough to work here safely now costs more than most single
items.** An agent taking one small item pays that cost and amortises it over
one change. The queue now says to take a batch sharing an entry cost — one
menu, one crate's whole surface, one subject across crates.

The floor has not moved. A batch is still made of whole items.

### What it actually came to

Measured on this machine, the full `-Linux` gate over the same tree:

| | Before | After |
| --- | --- | --- |
| Windows test stage | 107.8s | **46.3s** (36.4 test + 9.9 doctests) |
| Linux leg | 502s | **116s** |
| Whole gate, both legs | ~901s (15.0 min) | **432s (7.2 min)** |
| Windows gate executions per commit | 3 | **1** |

The Linux leg's share is larger than nextest alone explains: it had been
rebuilding from a cold cache, and installing nextest inside the distro warmed
it. Both numbers are honest for a repeat run, which is the case that matters,
because the gate runs many times per session and once per clone.

### A trap this design did not spring, and the one it did

While testing the evidence check, I reasoned that
`artifacts/test-evidence/*.json` is *tracked* — `.gitignore` has a comment
directly above it reading "deliberately NOT ignored — they are the evidence
behind ADR-0015" — and concluded that the gate's own record would invalidate
the gate's own evidence: written *after* `source_at` is taken, so newer than
the timestamp inside it the moment it was staged. Every record would declare
itself stale, and pre-push would re-run the full gate forever while appearing
to work.

**That was wrong, and the way it was wrong is the point.** The comment refers
to `artifacts/benchmarks/`, one clause earlier in the same sentence. The line
below it, `artifacts/test-evidence/*.json`, carries no `!` and is an ordinary
ignore rule. The records have never been tracked. `git check-ignore` answers
in a second and was not run until after the claim had been written into this
ADR, into two code comments, and into a commit message.

So this is **trap 3 — "a claim in a comment is not a property of the code" —
committed inside the ADR that names trap 3**, and it arrived by exactly the
route that trap describes: a comment was read as a statement about the rule
beneath it, and the rule was never asked.

The exclusion stays in both readers, now as a **guard rather than a fix**: if
those records are ever un-ignored, the self-invalidation is real, and it would
be invisible — the optimisation would silently never fire, which is the
failure mode that does not get reported. The comments say that, rather than
claiming to have prevented something that was happening.

Two things follow that are worth having:

- **The records are machine-local**, so there is no repository churn and the
  ten-file cap is about disk rather than history.
- **A fresh clone has no evidence and runs the full gate**, which is the
  correct answer and reaches it by failing closed rather than by design.

> **A general form, since this is the second time in one session:** when a
> comment sits above a rule, check which rule it is about. The reasoning built
> on top of it can be sound end to end and still be about the wrong line.

## Consequences## Consequences

- **Nothing about scrutiny changes.** The full `-Linux` gate is still required
  before a commit; the manual pass is still the thing no agent can do; "what
  would fail if this stopped being true?" is still the question that found
  both of this session's real defects. Every item above removes overhead, not
  checking.
- **The gate's evidence records became load-bearing.** They were provenance
  for the Definition of Done and nothing read them. Anything that changes
  their shape now changes pre-push's behaviour, and
  `Test-GateEvidence.ps1` skips records lacking the new fields rather than
  guessing.
- **A new failure mode, named so it is not a surprise:** touch a tracked file
  after the full gate and pre-push runs the whole thing. That is correct, and
  it will feel like a regression the first time it happens.
- `cargo-nextest` is now installed on this machine and in `Ubuntu-24.04`. A
  fresh clone is unaffected but slower.
- **`CLAUDE.md` is a file that will rot if it is allowed to grow.** Anything
  added to it should displace something, or belong in the file that owns it.
