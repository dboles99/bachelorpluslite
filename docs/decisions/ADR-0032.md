# ADR-0032: The Application Id Is Reverse-DNS, And Is Not The Directory Name

**Status:** Accepted
**Date:** 2026-08-20

## Context

`bp_platform::editor::AppIdentity::app_id` names the `.desktop` file, the
`x-scheme-handler` and MIME associations in `mimeapps.list`, the entry in
every desktop database on a Linux machine, and the `HKCU\Software\Classes`
ProgId shape on Windows. ADR-0012 already says the product registers itself
through OS-supported routes and never patches another editor, so this string
*is* how the operating system knows this product exists.

Today it is `"bachelorpad"`, and it is that because
`AppIdentity::bachelorpad` sets it from `crate::APP_DIR` — the constant that
names the *directory* the product keeps its files in. One string is doing two
jobs, and the doc comment on `app_id` already states the promise that makes
this urgent:

> the `app_id` in particular must not drift between releases.

It is free to change now and expensive the moment anyone installs. Changing it
later orphans every association a user has made: their `.desktop` entry, every
file type they pointed at this editor, and every `mimeapps.list` line naming
it. They do not break loudly — the old id simply stops being anything, and
files open in whatever the desktop falls back to.

## Decision

**The application id is `io.github.dboles99.BachelorPadPlus`, and it is a
separate constant from `APP_DIR`.**

Two changes, and the second matters as much as the first.

### Reverse-DNS, and this one

Reverse-DNS is the freedesktop convention, what Flatpak and Flathub require,
what AppStream metadata keys on, and what Windows expects of a ProgId prefix.
A bare `bachelorpad` is a name in a global flat namespace shared with every
other application on the machine, which is the thing the convention exists to
avoid.

`io.github.dboles99` is chosen over a `com.` domain because it is a namespace
this project demonstrably controls — `origin` is
`github.com/dboles99/bachelorpadplus_rust` — rather than a domain nobody has
registered. `io.github.<user>` is the standard form for exactly this case and
is what Flathub accepts for a project without its own domain. If a domain is
ever registered, that is a change to make *before* a release and not after,
for the reason this ADR exists.

The last component is `BachelorPadPlus` rather than `bachelorpad`: the
convention is that the final segment is the application's name in its own
capitalisation, and `+` is not a character a `.desktop` file name or a ProgId
can carry portably.

### `APP_DIR` stays `bachelorpad`, and stops feeding `app_id`

They are different questions with different constraints, and they were the
same string only by accident.

`APP_DIR` is a folder name a user reads in a file manager and types in a
terminal — `%LOCALAPPDATA%\bachelorpad\state`,
`~/.config/bachelorpad/config.toml`. Reverse-DNS there is worse for the person
looking at it, and it is not what the XDG convention asks for. The dot-leading
segments would also make `.io.github...` sort oddly and read as a hidden
directory to anyone skimming.

`app_id` is a machine identifier that must be globally unique and must never
change. Keeping one constant serving both means a future decision about either
silently moves the other — and moving `APP_DIR` moves the user's settings,
their recent list and their recovery journal.

## Consequences

- D9 leaves `project/DECISIONS_NEEDED.md`.
- `AppIdentity::bachelorpad` reads `APP_ID` rather than `APP_DIR`, and the two
  constants sit beside each other with this ADR named on both, because the
  next person to see two identical-looking strings will want to know why they
  are not one.
- The generated `.desktop` file name, the MIME package file name and the
  `<app_id>-file-types.reg` artefact name all change. Nothing is installed
  anywhere yet, so nothing is orphaned by making the change now — which is
  precisely the argument for making it now.
- `app_id` must satisfy `paths::is_portable_file_name`, which
  `AppIdentity::validate` already enforces, because it becomes a file name on
  both platforms. `io.github.dboles99.BachelorPadPlus` does: the stem before
  the first dot is `io`, which is not a reserved device name, and it carries
  none of the forbidden characters.
- A test should pin the *form* rather than the string — that the id has at
  least three dot-separated segments and is not equal to `APP_DIR` — so that a
  future domain change is a one-line edit and re-fusing the two constants is
  not.
- Nothing about the product's user-facing name changes. It is BachelorPad+ on
  screen, in the window title and in the `.desktop` entry's `Name=`. This is
  the identifier underneath it.
