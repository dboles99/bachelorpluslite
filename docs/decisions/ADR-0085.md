# ADR-0085: Legacy Encodings Are Read, And Saved Back As They Came

**Status:** Accepted -- not yet built (W2-04)
**Date:** 2026-09-25
**Answers:** D23
**Related:** [ADR-0006](ADR-0006.md), [ADR-0029](ADR-0029.md), [ADR-0059](ADR-0059.md)

## Context

A file in Windows-1252, Shift-JIS or GBK does not open once it holds a
single character outside ASCII: the product says it is *not valid UTF-8* and
stops. **UTF-16 with no byte-order mark fails the other way.**
`Encoding::detect_bom` falls back to UTF-8, and mostly Latin UTF-16 is valid
UTF-8 -- `A\0B\0` decodes as `A`, NUL, `B`, NUL -- so it opens, with a NUL
between every character. It saves back byte for byte, so nothing is lost; it
is only unreadable. (This ADR first said such files were refused. A review
of the pull request that carried it read `load` and found otherwise.)
`bp_core::Encoding` has four values -- UTF-8, UTF-8 with BOM, UTF-16 LE and BE
-- and the manual called that *"a decision rather than an unfinished one"*,
on the argument that a legacy code page is a way to lose text.

**No ADR made that decision.** It was a sentence in the manual. And its
argument points the other way once the user's position is taken into
account: a refused file is not protected, it is opened in Notepad instead. The
text that is at risk is the text this product never sees.

[ADR-0059](ADR-0059.md) scoped the product to Windows 11 Notepad plus a
note-organising layer. Notepad opens these files. Every "ANSI" file a Windows
user has saved in the last thirty years is one of them. This is the largest
single gap between the product and the thing it replaces, and on Windows it is
the one a new user meets first.

## Decision

**Open them, and save them back in the encoding they came in.**

- **Detection, in order:** a byte-order mark; then **the UTF-16 pattern**, an
  even length with NULs concentrated in the odd bytes (LE) or the even ones
  (BE); then valid UTF-8; then a guess by `chardetng`. The UTF-16 check must
  come before the UTF-8 one, because the case above passes UTF-8 validation
  and `chardetng` does not detect UTF-16 at all. A guess is shown in the
  status bar like any other encoding, so a wrong one is visible rather than
  silently applied.
- **Decoding and encoding** by `encoding_rs`, the WHATWG encoding standard's
  implementation, which is what Firefox uses. UTF-16 stays with the product's
  own code, which already writes it.
- **Save writes the encoding the file was opened in.** Nothing is converted to
  UTF-8 unless the user chooses it from Format > Encoding. That is the answer
  to the manual's objection: text is lost when a program changes an encoding
  without asking, and this one will not.
- **A character the file's encoding cannot hold is refused at save**, naming
  the character and offering UTF-8. `encoding_rs` would otherwise write an
  HTML numeric reference into a text file, which is a second way to lose text.
- **Format > Encoding offers UTF-16** alongside the two UTF-8 variants, so a
  user can get *out* of a legacy encoding as well as stay in one.

**Two new dependencies, named here as CLAUDE.md requires:** `encoding_rs`
(`(Apache-2.0 OR MIT) AND BSD-3-Clause`) and `chardetng` (`Apache-2.0 OR
MIT`), both by the author of the Encoding Standard's Gecko implementation.
Both must pass `cargo deny check licenses` when W2-04 adds them, and
`THIRD-PARTY-NOTICES.md` is regenerated then, not now.

**Not in the release candidate:** *Reopen with encoding*, for a guess that was
wrong. The status bar makes a wrong guess visible, and reopening is the
correction; it is 1.0 work.

## Verification (W2-04)

Golden byte vectors committed **before** the change, per trap 7: a
Windows-1252 file with `é` and `€`, a Shift-JIS file, a BOM-less UTF-16 LE
file, each opened and saved back byte for byte. A round trip through this
build proves nothing about a file Notepad wrote.

## Consequences

**Until W2-04 lands, the manual must say what is true today**: these files are
refused, and reading them is decided and not built. It no longer calls the
refusal a decision. And the website stopped saying *"Everything Notepad
does"* ([ADR-0089](ADR-0089.md)), which this gap alone made false.
