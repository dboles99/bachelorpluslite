# ADR-0016: Local-first CI

**Status:** Accepted
**Date:** 2026-08-17

## Context

GitHub Actions is not available to this project. Commits and pushes work
normally; only hosted CI cannot run. A repository carrying a CI configuration
that never executes is worse than one carrying none, because the config
implies a gate that is not there.

## Decision

The authoritative gate is local: `scripts/Invoke-LocalCI.ps1`, wired into
`pre-commit` and `pre-push` by `scripts/Install-GitHooks.ps1`. It runs
formatting, a locked dependency check, clippy with warnings denied, and the
test suite, with an opt-in Linux leg through WSL and an opt-in pass over the
standalone spike workspaces.

`.github/workflows/ci.yml` is kept, kept correct, and set to
`workflow_dispatch` only, so pushes do not queue runs that cannot execute.

## Consequences

- The gate only works once installed. `Install-GitHooks.ps1` verifies the
  executable bit, because a hook without it is skipped silently -- the
  hardest failure mode to notice.
- This machine sets `core.hooksPath` globally, whose pass-through stubs exec
  the repo-local hook. The installer therefore must not set a repo-local
  `core.hooksPath`, which would disable the global commit-msg hook.
- The hooks are bypassable with `BPAD_SKIP_CI=1`. That is deliberate: a gate
  with no escape hatch gets disabled wholesale the first time it is wrong.
- The local gate and the dormant workflow must be kept in step. Two gates
  that disagree are worse than one.
- Cross-platform verification depends on a Rust toolchain inside WSL. Without
  one, the Linux leg reports as skipped rather than silently passing.
