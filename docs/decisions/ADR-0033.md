# ADR-0033: OpenAI's API Is The Vetted Destination For Content That Leaves The Machine

**Status:** Accepted
**Date:** 2026-08-21

## Context

`bp_security::Network` already has the shape this needs -- `Allowed` and
`Denied`, checked by every profile -- but `Allowed` has never meant anything
beyond "this profile does not forbid it". Nothing in the application makes a
network call today. Phase 8's semantic/hybrid search and phase 10's later
layers are the first features that would, and both were blocked on the same
unanswered question: when one of them does call out, where is it allowed to
call to?

Baking in a provider list before anyone asked the question would have been an
answer nobody gave, about data leaving a user's own computer. That is a
different order of decision from anything else `Network` governs -- a profile
choosing to permit or forbid is the user managing risk they already
understand; naming the destination is the product deciding who else sees their
words.

## Decision

**OpenAI's API is the vetted destination**, when a feature under `Allowed`
needs one. Nothing else is pre-approved, and nothing calls it yet -- this
closes D1, it does not wire anything in.

Three things travel with it, and none are new inventions; they are ADR-0006
and ADR-0011's existing posture, restated for the first feature that will
actually reach the network:

1. **A feature that reaches this provider is opt-in per use, not per
   session.** `Network::Allowed` says the profile does not forbid it; it does
   not say the user asked for it *this time*. Phase 8's own design has to
   surface the moment content is about to leave, not rely on a switch flipped
   once and forgotten.
2. **`Network::Denied` still means nothing leaves, unconditionally.** This
   ADR narrows what `Allowed` may reach; it does not touch the profiles that
   forbid reaching anywhere, and ADR-0020's monotonic ordering keeps working
   exactly as measured.
3. **Nothing here authorises `bp-research`.** That crate is offline by
   ADR-0006, on purpose, and its own module documentation already says
   reaching the network from there needs an ADR that supersedes ADR-0006 and
   a human to write it. This is not that ADR -- see ADR-0039 for what
   research mode is instead.

## Consequences

- D1 leaves `project/DECISIONS_NEEDED.md`.
- Phase 8's design may now name a concrete destination rather than deferring
  the question a second time. What it sends, when, and under whose consent
  is still that phase's own design work.
- A single named provider rather than a list means one integration to build,
  one terms-of-service to track, and one outage to plan around. Adding a
  second is a decision to make when a second is actually wanted, not a
  default kept open in case.
- `bp-security`'s `Network` enum and its tests are unchanged by this ADR. It
  answers a product question `Network::Allowed` was always going to need
  answered downstream of it, not a change to the type.
