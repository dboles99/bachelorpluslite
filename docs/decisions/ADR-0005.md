# ADR-0005: Status Bar Reports Real Disk State

**Status:** Accepted
**Date:** 2026-08-16

## Context

specs.md section 3 requires the status bar to show both the last successful
disk save and the last recovery checkpoint, and states that a recovery
checkpoint must never be shown as a successful disk save. The two mean very
different things to a user deciding whether their work is safe.

## Decision

The status bar exposes the last successful disk save and the document's full
path. Disk saves and recovery checkpoints are modelled as distinct types
(`DiskSaveTime` and `CheckpointTime`) that are not interconvertible, so one
cannot be rendered where the other is expected.

## Consequences

- A checkpoint never clears the dirty flag.
- A document with no path shows an explicit "Location not assigned" rather
  than an empty row, because a blank field reads as a bug.
- Enforced by the type system in `bp-core`, not by reviewer vigilance.
