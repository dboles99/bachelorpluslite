# ADR-0090: A Document Is Saved In Its Own Line Ending, Unless Its File Arrived Mixed

**Status:** Accepted -- built 2026-10-01 (W1-06)
**Date:** 2026-10-01
**Narrows:** the save rule in `crates/bp-ui/src/state.rs`, which no ADR had recorded

## Context

Save wrote every document with `LineEndingPolicy::Preserve`: the text's line
breaks went to disk byte for byte. That rule was chosen against a real
defect -- the shell used to convert every break to the declared convention on
every save, which quietly rewrote the minority in a mixed file -- and a test
pinned it.

It had two consequences nobody had written down, and both are user-visible:

- **Every CRLF file anybody pressed Enter in came back mixed.** The text
  widget inserts `\n` for Enter whatever the file is. A Notepad file edited
  here and saved held `\r\n` on its old lines and `\n` on its new ones, while
  the status bar went on saying CRLF.
- **Format > LF and Format > CRLF converted nothing.** They changed the label
  and marked the document unsaved, and Save then wrote the bytes it already
  had. The comment above the save said a conversion was asked for there "and
  it asks first"; neither was true. Trap 3, in a comment that reads like a
  design.

## Decision

**A document is saved in its own convention -- the one the status bar shows
-- with one exception: a file that already held both conventions when it was
read, until somebody chooses one.**

| Document | Save writes |
| --- | --- |
| Opened from a file that was uniform, or new, or restored | Every break in the document's convention |
| Opened from a file that was already mixed | The breaks as they are (`Preserve`) |
| Either, after Format > LF or CRLF | Every break in the chosen convention |

The reasoning is about whose a stray break is. In a file that arrived uniform,
a break in the other convention was put there by this program -- Enter, or a
paste carrying whatever the clipboard held -- and Notepad, which this product
answers to, writes those in the file's convention. In a file that arrived
mixed, which break is the stray is not this program's to say, so it is left
alone until the user says, and **choosing a convention is how they say it**,
including the one the majority already is.

Save a Copy follows the same rule, because a copy written differently from a
save would be a different file.

A bare carriage return is data, not a break, and is never rewritten under any
row (ADR-0029).

## What it costs

- **A restored document is treated as uniform.** The checkpoint records the
  convention but not whether the file was mixed when first opened, so a mixed
  file recovered after a crash is saved converted. Rare twice over, and the
  direction it errs is the one Notepad takes for every file.
- **Reading a file now surveys its breaks once**, a byte scan the load already
  pays for in detecting the convention.

## Verification

Six tests in `bp-ui/src/state.rs`, on byte vectors committed before the
change (trap 7) -- a file as Notepad writes it, the same file as it must be
after Enter twice, and a file mixed before this program touched it:

- Enter in a Notepad file saves as CRLF -- **failed before**;
- Format > CRLF converts an LF file -- **failed before**;
- choosing a convention makes a mixed file uniform -- **failed before**;
- a copy is written as a save would be -- **failed before**;
- a file that arrived mixed is saved as it came, through typing and through
  an operation -- passed before and after, which is the point of them.

The second of those last two is the test that pinned `Preserve`. It now pins
it where it still belongs, and says so.
