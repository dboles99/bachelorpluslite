# ADR-0008: Structured Formats and Notebook Capability

**Status:** Accepted
**Date:** 2026-08-16

## Context

specs.md sections 7 to 12 require first-class handling of Markdown, YAML,
JSON, JSONL/NDJSON, TOML, INI, CSV/TSV, XML, common source languages and
Jupyter notebooks, including mixed-language cell execution.

## Decision

Formats are handled through a registry of format profiles rather than a
switch on file extension, so a profile can be selected by content, by user
override, or by extension. Notebook support targets the `.ipynb` format for
import and export.

## Consequences

- Adding a format is adding a handler, not editing a central match arm.
- Parsers operate on untrusted input and are therefore fuzz targets
  (specs.md section 23).
- Execution security is governed by ADR-0011: notebook code never auto-runs.
