# ADR-0083: Slint 1.18.1, Because 1.17.1 Could Not Draw Past Line 2,000

**Status:** Accepted
**Date:** 2026-09-25
**Answers:** D21
**Amends:** [ADR-0081](ADR-0081.md) (its fourth decision, "no upgrade to 1.18.1 in this change")
**Related:** [ADR-0017](ADR-0017.md), [ADR-0080](ADR-0080.md)

## Context

The release-candidate audit reproduced a crash in the default configuration:
open a document of about 2,100 lines -- or 1,100 at a display scale of 2 --
with the software renderer ([ADR-0017](ADR-0017.md)) and the default
`TextInput` surface, and a debug build panics:

```
panicked at euclid-0.22.14/src/point.rs:614:34:
attempt to add with overflow
```

and at `point.rs:597` at scale 2. **That message matters more than the
panic.** It is a debug-build overflow check, and the release profile does not
enable those, so a shipped build would not have crashed -- it would have wrapped
a coordinate and drawn the rest of the document somewhere other than where it
is. A crash is at least reported. D21 asked what to do about it: upgrade, or
move the default off the software renderer.

Slint 1.18.1's changelog lists *"Fixed a panic with very long lines of text
(#12994)"*, which is not obviously this, since these lines are short. So it
was tested rather than read.

## What was run

`slint` and `slint-build` at 1.18.1 on a separate worktree, `cargo update -p
slint -p slint-build`, a debug build, and the same repro against both
binaries under Xvfb:

| | 1.17.1 | 1.18.1 |
| --- | --- | --- |
| 2,100 lines | **panic**, `point.rs:614` | no panic |
| 1,100 lines, `SLINT_SCALE_FACTOR=2` | **panic**, `point.rs:597` | no panic |
| 5,000 lines | -- | no panic |
| 5,000 lines, scale 2, Ctrl+End, Page Up | -- | no panic, lines 4,966--4,989 drawn where they belong |

**A debug build is the stricter test**, because it is the one that checks the
arithmetic. The last row was confirmed by looking at the frame as well as the
log, because an absent panic says the addition did not overflow, not that
the text is in the right place.

It is rerunnable, and it fails loudly now:

```sh
FIXTURE_LINES=2100 scripts/drive-window-xvfb.sh "ctrl+End Z"
```

`drive-window-xvfb.sh` gained the fixture size and a check that fails the run
on any `panicked at` in the application's log. Against the 1.17.1 binary it
exits 1 and prints the panic, which is how the check was seen to work. Before
this, a panic that left the window up passed the harness.

## Decision

**Upgrade to Slint 1.18.1 and keep the software renderer as the default.**
The requirement is `"1.18.1"`, not `"1.18"`, because the fix is the reason
for the upgrade and a floor below it would let a fresh resolve choose the
version that crashes.

**The renderer does not change, so [ADR-0017](ADR-0017.md) is not amended.**
The fallback D21 carried -- the platform renderer by default -- would have
reopened the GL-fails-silently exit and the Wayland questions for a defect
that one version bump fixes.

**Nothing is virtualised.** Rendering only the visible rows would be the
durable answer to large documents, and it is what `--editor-view` already
does. It is not a release-candidate change.

## What else moved

- **ADR-0080's caret offsets survived.** `cursor-position-byte-offset` and
  `anchor-position-byte-offset` are internal Slint properties, and ADR-0080
  accepted them because their removal would fail at compile time. It did not
  fail: `app.slint` compiles unchanged against 1.18.1.
- **1.18 renamed `Flickable`'s `viewport-*` properties to `content-*`** and
  deprecated the old names, as a two-way alias
  (`@deprecated in property <length> viewport-height <=> content-height` in
  `i-slint-compiler-1.18.1/builtin_elements.rs`). The eight uses in
  `app.slint`, `menu.slint` and `list_panel.slint` are renamed, so the build
  is free of the 32 warnings they produced, and nothing else changes.
- **ADR-0068's image claim still holds.** 1.18.1 still builds `image` with
  `png` and `jpeg` only (`cargo tree -e features -i image`), so the window
  icon stays a PNG.
- **The lockfile lost more than it gained**: 58 crates left and 27 arrived.
  Most of what left is image codecs nobody decoded (`rav1e`, `exr`, `qoi`)
  and the old clipboard stack (`copypasta`, `smithay-clipboard`), which
  `arboard` replaced with `wl-clipboard-rs`. **`wgpu` and `naga` are in the
  lockfile and compiled for no target this product builds** -- `cargo tree -i
  wgpu -e normal` prints nothing -- because a lockfile records every optional
  dependency the graph could enable, not only what is built.
- `cargo deny check licenses bans sources` passes, and
  `THIRD-PARTY-NOTICES.md` was regenerated: 582 shipped crates, 30 licences.

**Input-method composition is still blocked**, as [ADR-0081](ADR-0081.md)
found in the 1.18.1 source. The upgrade changes none of its three answers.

## Consequences

**A debug assertion found a release defect that no release test could.** The
same overflow in a release build would have been a wrong frame, and nobody
checks frames. The tests and the Xvfb harness run debug builds, and that is
worth keeping for exactly this reason.

**"Checked against the changelog" would have got this wrong in both
directions.** The entry does not describe this bug, and the bug is fixed. The
repro took two minutes once the build existed.
