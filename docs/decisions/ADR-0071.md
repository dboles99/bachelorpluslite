# ADR-0071: The Licence Is GPL-3.0-only, And The `-only` Is The Decision

**Status:** Accepted
**Date:** 2026-09-10
**Supersedes the licence half of:** [ADR-0054](ADR-0054.md)
**Depends on:** [ADR-0074](ADR-0074.md)

## Context

This project is going public. That turns the licence field from an internal
detail into the terms strangers receive the software under, and the audit that
preceded it found the field was not supported by anything.

Every manifest said `MIT OR Apache-2.0`. ADR-0054 put those words there and
wrote both licence files, which fixed the defect it found -- *a claim with no
text behind it*. It did not ask the next question, which is whether the claim
was true of the thing being shipped.

**It was not.** `slint` 1.17.1, and the thirteen `i-slint-*` crates statically
linked with it, are published as:

```
GPL-3.0-only OR LicenseRef-Slint-Royalty-free-2.0 OR LicenseRef-Slint-Software-3.0
```

A tri-licence is an election the distributor makes. **This repository had
never made one, anywhere.** The archives shipped `LICENSE-MIT` and
`LICENSE-APACHE` and no Slint notice at all, so the one document a recipient
could read described the terms of a fraction of what they had downloaded.

That is trap 3 one level up from where ADR-0054 caught it. ADR-0054 asked
"is there a text behind this string?" and there was not, so it wrote one.
Nobody asked "is the string true of the binary?", and nothing in a build would
ever have said.

## Decision

**BachelorPad+ Lite is distributed under GPL-3.0-only.** `LICENSE-MIT` and
`LICENSE-APACHE` are removed; `LICENSE` carries the GNU General Public
License version 3, verbatim.

### Why GPL-3.0 is the right answer rather than a merely available one

The election was going to have to be made in any case. Of the three branches
Slint offers, GPL-3.0-only is the one that needs no further conditions read,
tracked or complied with, and it is the branch Slint itself documents as the
open-source option. Electing it costs this project nothing it wanted: the
product is being published as free software.

The dependency graph does not object. A census of all 651 packages in
`Cargo.lock` found MIT, Apache-2.0, BSD-2 and -3-Clause, Zlib, ISC, BSL-1.0,
Unicode-3.0, CC0 and Unlicense, and nothing else. **Every one is one-way
compatible with GPL-3.0**: permissive terms may be combined into a GPL-3.0
work. Not one crate had to be dropped, replaced or argued about.

### `-only`, not `-or-later`, and this is the part worth the ADR

The request that started this work asked for "GPL 3.0". The conventional
spelling of that in a Rust manifest is `GPL-3.0-or-later`, and it would be
wrong here.

**Slint's grant is to version 3 and no other.** A project offering
"or later" offers a recipient the option of a future GPLv4 -- and this project
cannot grant that for the parts of the work it did not write. The combined
binary would be offered under terms one of its major components has not been
licensed under.

That is the same defect the field had before, one version on: a licence string
promising more than the thing behind it delivers. Getting it right is the
difference between a relicence that fixes the problem and one that moves it.

## What makes this claim readable, so it can fail

Four readers, because the failure mode being fixed is a claim nothing consults:

1. **`--version` and the About box** print `env!("CARGO_PKG_LICENSE")`. The
   About box did not -- it carried `"Licence: MIT OR Apache-2.0"` as a string
   literal while `bp_config::cli::Package::license`'s doc comment three crates
   away said the workspace manifest was "the one home for this string". Trap 4,
   verbatim, and *found by planning this relicence rather than by anything that
   could fail*. `about_text()` is now a function with tests behind it, one of
   which asserts no licence name appears in it that the manifest does not
   declare.
2. **`deny.toml`,** run by the gate as the `licences` stage. The allow-list is
   the audit above, written down; a `cargo add` of an AGPL or SSPL crate fails
   the gate rather than shipping.
3. **`THIRD-PARTY-NOTICES.md`,** generated by
   `scripts/New-ThirdPartyNotices.ps1` from the resolve graph walked from the
   `bachelorpad` binary along normal and build edges -- 626 crates, never the
   dev-only ones, because a notices file naming `proptest` over-claims.
4. **The gate's `notices` stage,** which regenerates and compares. A generated
   file's only failure mode is staleness, and staleness is what nothing
   notices.

## Consequences

**Both release archives change contents.** `LICENSE` and
`THIRD-PARTY-NOTICES.md` replace the two licence files, and `BUILD.txt` reads
its licence line out of `--version` rather than carrying a literal.

**Dual licensing stays available and needs care.** Daniel holds copyright in
all of this code, so publishing it as GPL-3.0-only forecloses nothing about
BachelorPad+ full. **An outside contribution does not inherit that freedom**:
a pull request accepted into this repository is GPL-3.0-only from its author,
and moving it into a proprietary build needs that author's permission.
`CONTRIBUTING.md` says so before the first PR rather than after.

**A proprietary BachelorPad+ needs its own Slint election.** It cannot take
this one. That is a note for the other repository and is recorded here because
this is where the reasoning lives.

## The lesson

> **"Is there a text behind this claim?" and "is this claim true?" are
> different questions, and answering the first one well is what stops anybody
> asking the second.**

ADR-0054 found a licence field with no licence files and fixed it properly --
correct SPDX expression, both texts committed, the string threaded into
`--version`. The repository then had a licence claim that looked thoroughly
handled, and looking thoroughly handled is exactly what kept anyone from
noticing it described a fraction of the binary.

The check that catches it is not about licences at all: **name the thing the
claim is about, then go and look at that thing.** The claim was about a
21 MB executable. Nobody had looked at what was in it.
