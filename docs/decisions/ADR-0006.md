# ADR-0006: Core Editing Never Depends on Semantic or Cloud Features

**Status:** Accepted
**Date:** 2026-08-16

## Context

BachelorPad+ positions itself as "Notepad when you want it". That promise
fails the moment opening a file needs an index, a model, or a network call.

## Decision

Core editing -- open, type, save -- must work with every semantic, research,
notebook, clipboard-history and cloud feature disabled. Optional services may
enrich the editor but may never become prerequisites for it.

## Consequences

- The dependency direction in `docs/architecture/ARCHITECTURE.md` is one-way:
  UI to core to files, with semantic services hanging off the side.
- `bp-core` depends on no other `bp-*` crate.
- Any feature that would put a service on the open/save path needs an ADR
  superseding this one.
