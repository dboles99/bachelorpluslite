# ADR-0094: 1.0 Ships Unsigned, And Untested With A Screen Reader

**Status:** Accepted
**Date:** 2026-10-01
**Amends:** [ADR-0086](ADR-0086.md) (signing), [ADR-0088](ADR-0088.md) (accessibility)

## Context

The release-candidate plan of 2026-09-25 defined a release candidate,
`0.9.6-rc.1`, and reserved two things for 1.0:

- **a signed Windows binary** -- ADR-0086 made SignPath Foundation the 1.0
  route and the Microsoft Store the parallel one, both with weeks of lead
  time and neither applied for yet;
- **a pass with NVDA and Orca** -- ADR-0088 built keyboard reach and
  accessible names for the release candidate and made a screen-reader pass
  the gate for calling anything accessible.

On 2026-10-01 Daniel asked for **v1.0.0** for Windows 10/11 and Linux, rather
than a release candidate, and was asked about signing first. His answer:
**ship 1.0.0 unsigned.**

## Decision

**1.0.0 is the first public release, and it is unsigned and not yet tested
with a screen reader.** Neither is hidden.

- **Signing moves to a 1.x release.** SignPath Foundation remains the route,
  and the Store the second one, exactly as ADR-0086 set them out; what moves
  is only which version waits for them. The installation page and every
  release's notes say the downloads are unsigned, what SmartScreen and Smart
  App Control will do, and how to verify the checksum.
- **The screen-reader pass moves to a 1.x release.** What ADR-0088 built ships
  -- F10 reaches the menus, every control has a name -- and **the product
  still claims accessibility nowhere** until somebody has used it with NVDA
  and Orca. ADR-0088's own rule, *"accessible is not claimed anywhere until
  1.0's pass has happened"*, now reads *until the pass has happened*.
- **The version is 1.0.0, not 0.9.6.** The number says what the product is
  -- every release-candidate blocker in the 2026-09-25 plan closed, and a
  stranger can download it, edit, save and recover without losing a
  character -- and what it is not is said in words beside it rather than
  carried in a version number nobody reads as a caveat.

## What it costs

- **SmartScreen warns on every download until a signature exists**, and Smart
  App Control on Windows 11 may refuse to run it at all. That is the cost
  ADR-0055 first accepted, carried into 1.0.
- **A screen-reader user may find defects nobody has looked for.** The
  AT-SPI tree has been read and asserted under Xvfb; nobody has *listened*
  to it. The README says so.
- **winget, which ADR-0086 made a 1.0 task, follows signing**, for ADR-0086's
  reason: a signature is what makes a package-manager listing worth having.

## What would change the answer

Nothing reverses this -- 1.0.0 will have shipped. What it schedules is the
1.x release that carries the signature and the screen-reader pass, and the
SignPath application is the longest lead item in it: Daniel's to start.
