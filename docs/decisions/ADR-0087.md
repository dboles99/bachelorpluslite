# ADR-0087: The Linux Build Runs On glibc 2.35 And Later

**Status:** Accepted -- not yet built (W3-01)
**Date:** 2026-09-25
**Answers:** D25
**Related:** [ADR-0001](ADR-0001.md), [ADR-0072](ADR-0072.md), [ADR-0073](ADR-0073.md)

## Context

A Linux binary asks for the glibc of the machine it was **linked on**, not the
oldest one its code could use. `release.yml` builds on `ubuntu-latest`, which
is Ubuntu 24.04, and the binary it produces needs glibc 2.39:

```
readelf -V bachelorpad | grep 'GLIBC_2.39'     # Flags: none -- a hard requirement
objdump -T bachelorpad | grep 'GLIBC_2.39'     # pidfd_spawnp, pidfd_getpid, from std
```

The two symbols are *weak* references -- Rust's standard library uses them
when present -- but the version requirement is not, so the loader refuses
the whole binary on anything older: *version `GLIBC_2.39' not found*. That
excludes Ubuntu 22.04, Debian 12 and Linux Mint 21, which between them are
most of the Linux desktops in use today. [ADR-0001](ADR-0001.md) makes Linux
an equal target, and nothing recorded which Linux.

The floor was chosen by a runner label, `ubuntu-latest`, and would have moved
again, silently, the next time GitHub advanced it.

## Decision

**Build the Linux release on `ubuntu-22.04`**, which puts the floor at glibc
2.35: Ubuntu 22.04 and later, Debian 12 and later, Linux Mint 21 and later,
Fedora 36 and later.

- **The floor is enforced, not described.** `release.yml` gains a step that
  fails when `objdump -T` finds any `GLIBC_` version above 2.35. A floor
  written in a README and not checked is trap 3, and a runner image update
  would break it without anyone changing a line.
- **`ci.yml`'s Linux leg builds on the same image**, so a dependency that
  needs a newer glibc fails a pull request rather than a release.
- **The floor is stated** in the README, the installation page and every
  release's notes.
- **Declined for now:** RHEL 8 and 9, and Debian 11. Reaching them means
  linking against glibc 2.28 with `cargo-zigbuild`, which is a new tool in the
  release path for users nobody has asked on behalf of. It is the answer if
  somebody does.

## Consequences

**Pinning a runner means it will one day be retired**, and GitHub announces
that months ahead. When it happens, the choice is re-made from this ADR --
move to the next LTS image and accept its floor, or move to `cargo-zigbuild`
and keep this one -- rather than by whatever `-latest` means that week.

**Until W3-01 lands, the release-candidate plan counts this as a blocker**,
because a Linux user on the most common distribution would download a binary
that does not start.
