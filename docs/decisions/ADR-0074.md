# ADR-0074: The Product Is BachelorPad+ Lite, And Eight Places Said Otherwise

**Status:** Accepted
**Date:** 2026-09-10
**Depends on:** [ADR-0032](ADR-0032.md), [ADR-0054](ADR-0054.md)

## Context

Going public fixes a name or sets it in stone. The audit that preceded it
found **five spellings in current use**:

| Spelling | Where |
| --- | --- |
| `bachelorpluslite` | the repository |
| `bachelorpad` | the binary, and `APP_DIR` |
| `BachelorPlusLite` | `DISPLAY_NAME`, the window, the About box |
| `bachelorpadplus-0.9.5-*` | the release archives |
| `io.github.dboles99.BachelorPadPlus` | `APP_ID` and the icon filename |

and a sixth in use by the person who owns it: *bpad+ lite*, which is also what
the domain says -- `bpad.prompt-forge.dev`.

None of these is wrong on its own. Together they mean a visitor who downloads
`bachelorpadplus-0.9.5-windows-x86_64.zip` from a site called *bpad* runs a
program that calls itself *BachelorPlusLite*, and none of the three tells them
it is the Lite edition of anything.

## Decision

**The product is `BachelorPad+ Lite`.**

| | Was | Is |
| --- | --- | --- |
| `DISPLAY_NAME` | `BachelorPlusLite` | `BachelorPad+ Lite` |
| Archive stem | `bachelorpadplus-` | `bachelorpad-lite-` |
| Binary | `bachelorpad`, `bpad` shim | unchanged |
| Repository | `bachelorpluslite` | unchanged |
| `APP_ID`, `APP_DIR` | as ADR-0032 set them | unchanged |

The name matches the domain and makes the relationship to the full
BachelorPad+ legible, which is the thing the waitlist page depends on a
visitor understanding without being told.

**The repository is not renamed.** It would change the clone URL and break the
remote of the branch ADR-0053's PR is open against, in exchange for tidiness
in a string most users never see.

**`APP_ID` is not changed either, and that is a deferral rather than a
decision.** ADR-0032 chose `io.github.dboles99.BachelorPadPlus` and it is the
identity written into `mimeapps.list` on every machine that has registered a
file type. Changing it means renaming a committed asset, which needs explicit
approval, and it raises a real question this ADR does not answer: **the full
BachelorPad+ would want that same identifier**, and two products sharing an
`APP_ID` is a collision waiting for whoever installs both. It is written down
here so that it is asked before the full version ships, rather than found.

## The part that is worth the ADR

`DISPLAY_NAME` exists so that this rename is one edit. Its doc comment has
said so since it was written:

> it carries no compatibility promise at all -- this one may be changed
> freely, which is precisely why it must not be spelled out at the three
> places that show it

and then, added after the last rename went wrong:

> **Which is exactly what happened.** The identity change renamed the window
> title and the About box by hand and left this constant alone, so for a week
> the product introduced itself as BachelorPlusLite in the window and
> BachelorPad+ at the command line.

That is trap 3 answered honestly and trap 4 recorded. The test written in
response -- `version_names_the_product_the_desktop_registration_names` -- has
passed ever since, and the comment says why: *both halves of that pair read
this*.

**Which is the whole defect. The pair test proves the pair agrees.** It says
nothing about anywhere else, and this rename found the name spelled out at
**eight** sites, not the three the comment names:

1. `app.slint` -- the window title, a toolkit literal Rust never touched
2. `menus.rs` -- the About row label
3. `dispatch.rs` -- the About dialog title
4. `dispatch.rs` -- the About body
5. `lib.rs` -- the unsaved-work recovery prompt
6. `state.rs` -- the Help > Diagnostics report
7. `main.rs` -- the start-up log line
8. two module headers

Every one now reads `DISPLAY_NAME`. The window title is set from Rust through
a new `app-title` property, because a literal in a `.slint` file is a second
home that no Rust test can see -- and it is the site the previous rename
actually broke.

Three tests ask, at three of the sites rather than at the constant:
`the_about_box_must_read_the_product_name_rather_than_spell_it`,
`the_about_row_must_read_the_product_name_rather_than_spell_it`, and
`the_diagnostics_report_must_read_the_product_name_rather_than_spell_it`.

## Consequences

**The archive names change**, so the download links on the website and the
example in `project/NEXT_SESSION.md` change with them.

**`--version`, About, the window, diagnostics, the recovery prompt and the
desktop registration cannot disagree**, because there is one string and six
readers rather than six strings.

**`APP_ID` and the full product's identity is an open question**, recorded
above and belonging to the other repository's first release rather than this
one's.

## The lesson

> **A test that proves two things agree is evidence about two things.**

`version_names_the_product_the_desktop_registration_names` is a good test. It
was written to catch precisely the failure that had just happened, it catches
it, and it passed every single run while six other sites carried the name as a
literal.

The reason is in its name. It asserts a *pair*. The doc comment beside the
constant claimed *three* places, which was already an undercount, and the
number nobody had was **how many sites there actually are** -- which is one
`grep` and was never run, because the test was green.

**The check is to count, not to test.** Before trusting that a constant is the
one home for a value, grep for the value. If the count is higher than the
number of readers, the constant is a convention rather than a mechanism.
