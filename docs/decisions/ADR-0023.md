# ADR-0023: YAML uses `saphyr`, and What That Costs

**Status:** Accepted
**Date:** 2026-08-19

## Context

specs.md section 7 lists YAML as a first-class format and section 9 wants
validate, format, sort keys, duplicate-key detection and conversion for it.
`bp-formats` has recognised `.yaml` and `.yml` since phase 5. `bp-data` did
not touch it, because the parser was an open question: `serde_yaml` — the
obvious answer, and the one most Rust projects still carry — was deprecated by
its author in 2024 and is no longer maintained.

Every other structured format in `bp-data` is one line of parsing over a crate
that behaves. YAML is not, and pretending otherwise is how a formatter ends up
quietly deleting half a file.

## Decision

### `saphyr` is the parser

`saphyr` is the maintained successor to `yaml-rust2`, itself the maintained
fork of `yaml-rust`. It is the only one of the candidates that claims and
tests YAML 1.2 compliance. `serde_yaml` is deprecated and is not to be added
to this workspace.

`saphyr-parser`, its event-level half, is taken directly as well. It is not an
optional extra: two of the decisions below can only be made before a tree
exists, and the event stream is the only place to make them.

`default-features = false` drops `encoding_rs`. Every caller in `bp-data`
hands over a `&str`; the encoding-sniffing half has no reader here.

### Nesting is capped at 128 levels, and it is *not* a taste judgement

`saphyr_parser`'s loader walks a document through `load_node` ->
`load_sequence` -> `load_node` mutual recursion, one stack frame per level. A
stack overflow aborts the process; it is not an error anyone can be shown.

Measured on the 1 MiB main thread, a chain of nested block mappings survives
280 levels and dies at 290 in an unoptimised build (500 and 1000 in a release
one). The input that does it is **200 bytes**, so file size is no protection
and neither is trusting the source: a 200-byte paste crashes the editor.

The cap is enforced by counting depth over the parser's *event* stream, which
is a state machine over an explicit `Vec` and does not recurse — it reads
100,000 levels without touching the stack. Counting after loading would be
counting after the crash.

128 is the limit `serde_json` already enforces on the JSON path next door, so
both formats refuse at the same depth and the shell has one sentence to say
rather than two. It leaves better than a factor of two against the tightest
build measured.

### Alias expansion is capped at 1,000,000 nodes per document

`saphyr` resolves `*name` into a copy of what it points at while loading. Ten
anchors, each a sequence of ten references to the one before, is 10^10 nodes
from about 200 bytes — the "billion laughs" document, and it is ten levels
deep, so the nesting cap does not see it. The expanded size is counted on the
same event pass, with each alias charged at the size of what it expands to.

### A duplicate mapping key is an error, not a merge

`saphyr` overwrites the earlier value on the way into the map, so by the time
there is a tree the first value is gone and there is nothing left to report.
Formatting such a file would delete a line and report success — the exact
failure `bp-data`'s module rules forbid. Only the events still know both were
there, which is the second reason `saphyr-parser` is a direct dependency.

Keys are compared the way the loader compares them, so `1` and `'1'` stay two
keys. A key carrying a tag is left out of the check: the loader keeps the tag
as part of the key's identity and `Scalar` does not, and comparing without it
would report two distinct keys as a duplicate.

### Every document in the file is handled

A YAML file carries a stream of documents separated by `---`. `yaml_validate`
checks all of them, `yaml_format` and `yaml_minify` write all of them back.
Taking only the first is the shape a `&str -> Result<String>` signature
invites, and it would silently delete the rest.

`yaml_to_json` is the exception, because JSON has a single root value. One
document converts; none converts to `null`; more than one is refused, naming
the count. Wrapping several documents in a JSON array would produce a
different shape from the document the user was looking at, and inventing it
would hide the mismatch instead of naming it.

### Formatting loses comments and expands aliases, and the caller must say so

`saphyr` parses YAML into data. A comment is not data, so a round trip through
the tree has nothing to put back. An alias is resolved during loading, so the
output repeats a value rather than referring to it.

Both preserve what the document *means* while changing what it says. This is
the same trade `toml_format` already makes and did not document. It is
recorded here because it is the one place in `bp-data` where "never silently
change the user's data" needs a warning in the UI rather than an error in the
library — a menu row that offers Format YAML without saying comments will go
is a trap.

## Consequences

- Two workspace dependencies, `saphyr` and `saphyr-parser`, pinned together.
  They release in lockstep and a version skew between them is a compile error
  rather than a subtle one.
- `bp-data` has two public constants, `MAX_YAML_NESTING` and
  `MAX_YAML_NODES`, because a refusal the user can see needs a number the code
  and the message agree on.
- Two defects in `saphyr` 0.0.12's emitter are worked around here rather than
  waited on, both found by the round-trip property test rather than by anyone
  thinking of them:
  - it writes Rust's `inf`, `-inf` and `NaN`, which YAML reads back as the
    *strings* `"inf"`, `"-inf"` and `"NaN"`. The value is handed to it
    pre-spelled as `.inf`, `-.inf` and `.nan` instead.
  - it writes a mapping key longer than 1024 characters as an implicit key,
    which YAML forbids, producing a file that will not parse on the next open.
    `yaml_format` refuses such a document; `yaml_minify` writes it correctly
    with the explicit `? key : value` form, so the refusal has somewhere to
    send the user.
  Both are worth reporting upstream.
- "Minify" for YAML means flow style. Whitespace is structural in block style,
  so there is nothing to strip; the compact form is a different syntax rather
  than the same syntax with the spaces taken out.
- Sort keys and outline/folding, both in specs.md section 9, are not done.
  `saphyr`'s mapping preserves document order and sorting it needs an ordering
  over YAML nodes that does not exist yet.
