# ADR-0022: The Encrypted Recovery Journal

**Status:** Accepted
**Date:** 2026-08-19

## Context

ADR-0020 gave two of the four security profiles `Recovery::Encrypted`, and
required that a policy which cannot be honoured fail loudly rather than
degrade. Until `bp-crypto` existed that meant Private and Confidential
documents got no crash recovery at all.

`bp-crypto` now exists (ADR-0021), which turns the question from "can we" into
a harder one: **an encrypted journal cannot be read at startup, because
nothing has a key yet.** The recovery prompt runs before any document is open.

Three ways out, and each costs something real:

1. **Prompt at startup** for each encrypted journal. Recovers everything
   without the user having to remember which file — but it trains them to type
   a passphrase at a prompt they did not initiate, which is precisely the
   habit phishing depends on.
2. **Store the path in clear** beside the ciphertext, so the prompt can name
   the document. Closest to how recovery works today, and it leaves a
   plaintext list of which files have unsaved work sitting in the recovery
   directory — close to what Confidential exists to prevent.
3. **Recover at unlock time.** Nothing is prompted; the journal is found when
   the user opens that document and gives its passphrase for their own
   reasons.

## Decision

**Recover at unlock time.** The journal is sealed with the document's own
passphrase and filed under a digest of the document's path.

### The whole checkpoint goes inside the ciphertext

Path, name, text, timestamp. Nothing is written in clear beside it. The
filename is a digest rather than the path itself.

### The digest is not a secret, and is not treated as one

Anyone holding the recovery directory can test a guessed path against it. It
hides *which* documents have unsaved work only from somebody who cannot guess
their paths, and it is not used for key derivation anywhere — keys come from
Argon2id via `bp-crypto`. What it buys over option 2 is that the directory no
longer reads as a list.

### A plaintext document under a strict profile still gets no journal

There is no key. The refusal is `Refusal::NoPassphrase` and it carries a
notice naming the fix: encrypt the document, and recovery comes back.

Passphrase is checked before path. For a document that is neither saved nor
encrypted both are missing, and "encrypt this document" is the more useful
thing to say — Encrypt Document is a Save As, so it supplies the path too.

### Both forms are kept in step

Every write of one deletes the other, in both directions:

- tightening a profile removes the plaintext journal, which is the case
  ADR-0020 already required;
- loosening one removes the sealed journal, which is the mirror and is easier
  to forget — a sealed copy left behind holds older work under a passphrase
  and would be offered at the next unlock;
- a successful save discards both, by id and by path.

### Recovered work marks the document modified

What is on screen is not what is in the file. Leaving the tab clean would let
the user close it and lose the recovered work without being asked.

## Consequences

- **Recovery for an encrypted document is invisible until it is opened.** A
  user who forgets which document they were editing gets no reminder. That is
  the accepted cost of never prompting for a passphrase unbidden.
- `Journal::sealed_count` exists so the shell can say *something* is waiting
  without saying what. Nothing uses it yet.
- A wrong passphrase at unlock recovers nothing and says nothing, because the
  caller has just opened the document with that same passphrase — so a failure
  means the journal is damaged, and a damaged journal is simply no journal.
- The sealed journal is keyed by path, so **moving a document orphans its
  journal.** Acceptable: the alternative is tracking documents across renames,
  which needs a stable identifier the filesystem does not provide.
- `bp-history` now depends on `bp-crypto`. `bp-security` still depends on
  neither, and neither depends on it: policy is decided in one place and
  performed in others.
