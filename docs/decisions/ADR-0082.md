# ADR-0082: Phase 10 Is Declined, And Four Policy Axes Nothing Enforced Leave With It

**Status:** Accepted
**Date:** 2026-09-25
**Supersedes:** [ADR-0056](ADR-0056.md)
**Amends:** [ADR-0020](ADR-0020.md), [ADR-0064](ADR-0064.md)
**Carries out:** [ADR-0059](ADR-0059.md) section 4, which ADR-0064 deferred

## Context

Phase 10 -- semantic and hybrid search -- was decided on 2026-08-23 without
being started ([ADR-0056](ADR-0056.md)): all three embedding sources as
choices, the profile as a ceiling, `None` as the default and `Cloud` behind a
per-use gesture. It became three queue rows, E1 to E3.

Then the product changed around it. [ADR-0059](ADR-0059.md) scoped the
reduction to Windows 11 Notepad plus a note-organising layer, and recorded
that E1--E3 were *not approved by having sat in a queue*. Ten crates left.
The product went public describing itself, in its repository's own
description, as having *"No network, no telemetry, no execution."*
`project/NEXT_SESSION.md` put the question plainly: semantic search is
further from Notepad than notebooks were, and notebooks were removed for
being too far.

Daniel asked for the phase to be decided, and this ADR decides it.

## Decision

**Decline phase 10.** Delete E1--E3 and do not replace them with a feature.

**Each of the three sources fails on its own terms here:**

- **`Cloud`** sends document content to a service. That contradicts the
  product's one-line description, and [ADR-0006](ADR-0006.md) before it. A
  consent gesture makes it permissible; it does not make it this product.
- **`Local`** means shipping or fetching model weights. The smallest
  sentence-embedding models worth the name are tens of megabytes, which would
  multiply the download of an editor whose archive is its binary, its icons,
  its licence and notices and its help pages, and put a model loader on the
  startup path of a product whose cold-start target is 150 ms to a window
  (specs.md section 22).
- **`None`** was the default, and the only value every user would have had
  until a provider shipped. It is also what the product does today.

**No replacement is built, because the need is already met.** The plan that
proposed this ADR offered lexical search over the note store as the
alternative. That did not survive taking the inventory: **the store holds
metadata and never content** -- path, title, timestamps and tags, by design
(ADR-0019, ADR-0037) -- so a search over it could only match titles and tags.
The reader's actual need, *find the note that says this*, is Find ▸ In Folder,
which searches the text of every file under a folder and is live. *What else
is about this* is Organize ▸ Related Notes. What embeddings would have added
is ranking by meaning rather than by words, and that is exactly the part that
needs a model.

**The `Embeddings` policy axis is removed, not left at `None`** -- and the
three other axes nothing enforced go with it.

`embeddings` was one of six fields on `bp_security::Policy`, carried a value
per profile, and was shown to users by Tools ▸ Security Inspector --
*"Embeddings: permitted, on this machine only"* -- in a product that computes
none. Removing it meant counting the other axes' readers, and three more had
none but that inspector:

| Axis | What the inspector told a Confidential document | What the product does |
| --- | --- | --- |
| `network` | leaves this machine: *never* | nothing leaves under any profile -- there is no HTTP or TLS client in the shipped graph and no socket in the code |
| `temporary_files` | *never written* | **every save writes one**: `atomic_write` puts a `NamedTempFile` beside the target and renames it into place, whatever the profile |
| `zeroise` | *buffers are overwritten when a document closes* | **nothing is wiped**; `zeroize` was a dependency of `bp-ui` that no code called, left over from the passphrase flow ADR-0064 removed |

Two of those three were false claims made to a user about their privacy, in a
published build whose description is a privacy claim. The third was true for
a reason the axis had nothing to do with.

**None of this is a new decision.** [ADR-0059](ADR-0059.md) counted every
enforcing reader, found these four at zero, and decided: *removed*.
[ADR-0064](ADR-0064.md) then deferred it -- *"cutting them is a second change
with its own consequences"* -- and reasoned that *"the doc comment on
`security_inspector_report` names which three govern nothing, so the readout
is not a claim the code fails to keep."* That is the flaw: **a user never sees
a doc comment.** They see the readout. A claim is kept or broken where it is
read, and this one was read in a window.

So all four leave, with their enums, their profile rows, their Privacy Mode
clamps, their inspector lines, and the `zeroize` dependency. `Policy` is two
axes -- `recovery`, read by the journal, and `metadata`, read by the store --
and its doc comment says so, where it used to say *"Seven axes, and every one
has a named reader"* over six fields, four of them unread.

`Policy` is never serialized -- it derives `serde` but nothing in the
workspace writes or reads one -- so the removal cannot break a config file, a
profile or anything `what_an_earlier_build_wrote.rs` holds.

**What was *not* decided, and is Daniel's:**

- **Confidential and Maximum are the same policy** -- `recovery: Disabled`,
  `metadata: Disabled` -- and were before this change: only the four removed
  axes ever told them apart. Two names for one policy is a question, not a
  thing to fix by inventing a difference.
- **Whether a profile should ever forbid the temporary file.** Enforcing it
  means a save that writes the document in place, which is the save that loses
  the document when the power goes during it. That is a real trade and it
  would come back as a new axis with its reader, not as this one restored.

## Consequences

**The product holds no planned feature it cannot justify.** That was the state
`project/NEXT_SESSION.md` said a "no" here would produce, and it does.

**A readout is where a policy's claim is kept or broken.** ADR-0064 had the
right facts -- it named the unenforced axes -- and put them where no user
would read them. Trap 3 says a claim in a comment is not a property of the
code; the sharper form here is that **a true comment does not make a false
screen honest.** The test beside the inspector now asserts that none of the
four lines comes back.

**The plan's own recommendation was the estimate this ADR corrected.** It said
"lexical search over the note store" without asking what the store holds.
*Take the inventory before the estimate* is `WORK_QUEUE.md`'s rule, and it
applies to a recommendation as much as to a queue item: the answer was one
`CREATE TABLE` away.

**If semantic search is ever wanted, this ADR says what it costs**: a network
exception to the product's headline claim, or a model on disk and on the
startup path, plus a policy axis to govern it. It would be a new ADR, not a
revert of this one.
