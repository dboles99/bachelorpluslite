# ADR-0048: Every Menu Row Either Works Or Is A Readout

**Status:** Accepted
**Date:** 2026-08-22

## Context

The goal set for this session was *every menu item working*. The obvious first
step looked like building 38 features: `menus::planned_menu` listed that many
rows across eight menus, each rendered greyed with a "not implemented yet
(phase N)" line beneath it.

**An inventory found that most of them had already shipped.** Printing every
menu's real rows beside its planned ones showed the planned lists had never
been pruned as features landed:

| Menu | Planned rows | Already live under another name |
| --- | ---: | --- |
| Security | 7 | **6** — encryption, Privacy Mode, the secret scanner, hashing, signing, redaction, the history |
| Data | 6 | **5** — Validate, Format, Minify, Sort Keys, Convert, all built per format |
| Insert | 5 | **3** — Date and Time, Code Block, Table |
| Note | 6 | **4** — Semantic Rename, Title, Summary, and Related Notes (in Organize) |
| Run | 5 | **1** — Stop |
| Notebook | 5 | **1** — Run Cell (in Run) |

So the "backlog" was mostly a list of finished work, and the genuine gap was
**21 rows**, not 38.

This is [ADR-0046](ADR-0046.md)'s lesson at ten times the scale:

> **A name that has sat in a plan long enough starts to read like a
> specification.**

And it had a second edge nobody had noticed. The Data menu, for a `.txt` file,
said *"— nothing for TXT documents"* and then listed six things under a
"phase 6" banner. It contradicted itself in one popup, and had done since the
Data menu was built.

## Decision

**Every row a user can see either performs an action or is a readout.** A
readout is a line that answers a question — the Security menu's policy lines,
"nothing to convert in a plain-text document", "open an `.ipynb`, or a `.md`
with fenced code blocks". A row that looks like a command and does nothing is
not allowed to exist.

`planned_menu()` and `arrives()` are **deleted**, not emptied. A menu that
announces a backlog is a menu somebody has to keep true, and this one was not
true for two phases.

Two tests hold the line: `no_menu_offers_a_row_that_does_nothing` and
`no_menu_says_a_feature_is_coming_later`, both sweeping a single list of every
menu so a menu added later cannot escape them.

### What was built

| Row | What it reads |
| --- | --- |
| Tools ▸ Security Inspector | The policy in force on **all seven** axes. The Security menu shows three; embeddings, temporary files and zeroising were governed invisibly. Shows the profile's own answer too wherever Privacy Mode overrode it |
| Tools ▸ File Analysis | The **file**, not the document — size, size class and what it implies, read-only, and whether it changed on disk |
| Tools ▸ Configuration | Every setting in force and where the config file is. **Read-only, and it says so** |
| Note ▸ Tags | What the store recorded for this document, and that tags are extracted at save rather than set by hand |
| Note ▸ Recovery Checkpoints | What the journal holds, and — before the count — whether this profile writes one at all |
| Notebook ▸ Export as .ipynb | A `.md` with fenced blocks out as a Jupyter notebook. The other end of ADR-0045 |
| Organize ▸ Suggested Folder | Where documents sharing this one's tags already live. **Counted from what the user filed, not a scheme imposed on them.** Never moves a file |
| Run ▸ Run Document | A `.py`/`.ps1`/`.sh` run whole. Takes a `UserGesture` by value, exactly as `run_cell` does |
| Run ▸ Interpreters | Which interpreter each language resolves to, and what it tried when none was found |
| Security ▸ Lock Document | Forget this document's passphrase now |

`bp-execution` gained `Language::all`, `Language::interpreter` and a public
`candidates`; `bp-storage` and `bp-semantic` needed nothing new.

### What was deleted, and why each

Deleting is the other half of the decision, under
[ADR-0047](ADR-0047.md)'s third standing authority.

**Already live elsewhere** — a second entry point is how one of them goes
stale: Note ▸ Related Notes (Organize has it), Notebook ▸ Run Cell (the Run
menu lists one row per cell).

**Contradicted by a decision this product has already made:**

- *Notebook ▸ Run All* — ADR-0038's model is a fresh subprocess per cell with
  no persistent session, so cell two cannot see cell one's variables. "Run
  All" means something specific to everyone who has used a notebook, and it is
  not what this would do.
- *Notebook ▸ Enable Notebook Mode* — there is no mode to enable; ADR-0043
  made a notebook reachable by opening one.
- *Notebook ▸ New Cell* — ADR-0043 declined a cell-sequence view. For a `.md`,
  a new cell is a fenced block, which Insert ▸ Code Block already writes.
- *Run ▸ Rust Scratchpad* — Rust is compiled. Every runner here hands source
  to an interpreter; this would need cargo, a temporary crate and a build
  step.

**A half-feature by this repository's own standard** — works in one of the two
editor views only: *Run ▸ Run Selection*, and *Edit ▸ Multi-cursor*, which
additionally needs `bp-editor` to carry a set of carets through every command,
selection and undo entry. Multi-cursor is a real feature and comes back as a
queue item with a design behind it.

**Promises the product cannot keep:**

- *Tools ▸ Benchmarks* — `benches/` holds a README and no benchmark.
- *Organize ▸ Semantic Search* — needs embeddings. The policy has an
  `Embeddings` axis and nothing computes one; doing so reaches
  [ADR-0033](ADR-0033.md).
- *Organize ▸ Project* — nothing in this product has a concept of a project,
  and inventing one to fill a row is how a feature nobody asked for gets
  built.
- *Organize ▸ Topics* — already in two places: Note ▸ Tags for the document,
  Research Report's dominant themes for the store.

### D14 is answered: no Markdown preview

**Slint 1.17.1 has no rich-text item** — no styled runs, no spans — so bold
inside a sentence is not representable. A preview that silently dropped inline
formatting would be worse than none.

The alternative, HTML handed to the system browser, means writing the
document's text to a temporary file in plaintext — which is exactly what
`Policy::temporary_files` exists to forbid for a Confidential document. It
would also need a Markdown-to-HTML dependency and a platform-specific opener.

Most of what a reader wanted exists: Note ▸ Outline, Notebook ▸ Cell Outline,
and Run for the blocks themselves. **Revisit if Slint ships styled text.**
*Split* — two panes over one document — is a separate feature and was never
the hard half.

### Two renames, both the "DOI Lookup" correction

- *Choose Interpreter* → **Interpreters**. An interpreter is resolved by a
  fixed fallback chain, not chosen; letting a user point the runner at an
  arbitrary binary is a security decision rather than a menu row. What the row
  can honestly do is answer *why did my cell not run*.
- *Revision History* → **Recovery Checkpoints**. `bp-history` is a
  crash-recovery journal, not a version store: it holds the pending checkpoint
  and discards it the moment a save succeeds. Revision History would promise
  successive versions to go back to.

## Consequences

- **`docs/product/MENU_MAP.md` has no planned row left in it.** Every menu is
  complete, and the file now records what each does rather than what it will.
- **`planned()` survives with a narrower meaning**, documented at its
  definition: a readout, never a promise. Every remaining caller is one.
- **A test asserted the old state and was inverted rather than deleted.**
  `the_security_menu_no_longer_calls_the_history_planned` required Lock
  Document to still be planned. Deleting the assertion would have left nothing
  watching, so it now requires the opposite.
- Ten new action ids across five blocks; every one is in the id-window test.
- **The count that mattered was never 38.** An inventory taken before building
  anything is what turned a session's worth of features into ten builds and
  eleven deletions — and the deletions carry more information than the rows
  would have.
