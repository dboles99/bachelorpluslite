# ADR-0035: The `.bpadx` Validation Ceiling Is Lowered, Not Removed

**Status:** Accepted
**Date:** 2026-08-21

## Context

ADR-0021 already refuses an absurd Argon2id cost outright: `KdfParams::validate`
bounds `memory_kib` to 1 GiB, `iterations` to 64 and `lanes` to 64, and a file
outside those is refused in microseconds before a single byte of key
derivation runs. That bound works exactly as designed.

What it does not bound is the space *inside* it. A header is untrusted input
read before anything is authenticated -- a tag check needs a key, so the cost
has to be paid before the file can be told apart from garbage -- and every
value up to the existing ceiling is legal. Measured in release: 8 KiB takes
46 µs, 1 GiB takes 2.1 s, and 64 MiB at 64 passes takes 4.7 s. Combined near
both maxima at once, `validate`'s worst case is roughly **75 seconds and a
gigabyte resident, per attempt, before the user is told the file is
damaged**. A tab full of hostile files, or one file opened twice while
impatient, multiplies that.

Two honest answers existed: bound by declared cost, which risks refusing a
document some future, deliberately stronger default actually sealed with; or
bound by wall-clock regardless of what the header claims, which never
rejects a legitimate document but makes "refused" and "slow" the same
observable event to a user watching a spinner. D10 chose between them.

## Decision

**The declared cost is capped lower, not replaced with a clock.**
`KdfParams::validate` moves from `memory_kib <= 1024 * 1024` and
`iterations <= 64` to:

- `memory_kib <= 256 * 1024` (256 MiB, down from 1 GiB)
- `iterations <= 16` (down from 64)
- `lanes` unchanged at `<= 64` -- parallelism divides the same total memory
  across lanes rather than multiplying the work, so it is not the lever the
  measured worst case turns on

Extrapolated linearly from the same measurements above, this brings the
worst case from roughly 75 s down to single-digit seconds, while leaving a
document sealed at the new ceiling **13 times the memory and 8 times the
iterations of the OWASP baseline this product already ships as its
default** -- room for a document that wants to be meaningfully stronger than
default without room for a header to demand a gigabyte and a minute from
whoever tries to open it.

The alternative -- bounding by wall-clock instead of declared cost -- was not
taken. It protects the machine identically, but it means the same file can be
refused on a slow machine and accepted on a fast one, and "your document
failed to open because this computer took too long" is a worse failure mode
for a legitimate user than "this document asks for more work than this
version accepts."

## Consequences

- D10 leaves `project/DECISIONS_NEEDED.md`.
- **Implemented.** `KdfParams::validate`'s two constants are changed, and a
  new test, `a_memory_cost_that_was_valid_under_the_old_ceiling_is_now_refused`,
  pins the tightening itself -- a value legal under the old 1 GiB bound and
  refused under the new 256 MiB one -- so `an_absurd_work_factor_is_refused_
  rather_than_attempted`'s 64 GiB case alone would not have caught a future
  accidental widening back toward the old ceiling.
- **Measured in release, not only extrapolated:** the worst case at the new
  ceiling (256 MiB, 16 iterations, 64 lanes) is **~5.56 s**, down from the
  ~75 s the old ceiling allowed. Close to this ADR's own linear extrapolation
  (~8 s), and confirms the new bound does what it was chosen to do.
- The OWASP-baseline default (19 MiB, t=2, p=1) is unaffected -- every
  document sealed today still opens in 50-100 ms, unchanged.
- A document sealed by a future build at a cost between the old ceiling and
  the new one would be refused by a build carrying this ADR. That is the
  trade the "cap the declared work factor" answer accepts on purpose:
  nothing has shipped a cost that high yet, so nothing existing is orphaned
  by tightening it now, and a future default strong enough to want more than
  256 MiB is a decision to raise this ceiling deliberately, the same way this
  one lowered it.
