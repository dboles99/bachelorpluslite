# ADR-0089: The Website Claims Only What Ships, And Names No Date

**Status:** Accepted
**Date:** 2026-09-25
**Answers:** D27, D28
**Amends:** [ADR-0076](ADR-0076.md) (withdraws the countdown and the date)

## Context

The release-candidate audit read the website against the product, and three
sentences on the front page were false:

| Said | True |
| --- | --- |
| *"Everything Notepad does, plus one thing it cannot"* | No printing, no legacy encodings ([ADR-0085](ADR-0085.md)), no choice of typeface, no spell check, no session restore |
| *"Nothing is written outside that folder until you ask"* | Settings, recent files, the recovery journal and the notes index live in the per-user profile, and the journal starts writing the moment there is unsaved work |
| *"Uninstalling is deleting the folder"* | Uninstalling is deleting the folder and three profile directories |

**The installation page contradicted itself on the second.** Its opening said
nothing is written outside the program's folder; its own table, forty lines
later, said nothing is written *inside* it. And its first-launch section said
nothing would be written until the first save, which the recovery journal
makes false by design.

Then there was the date. [ADR-0076](ADR-0076.md) put a countdown on the
waitlist page to BachelorPad+ arriving on **10 October 2026**, and recorded
that this made the page *a public commitment to a date*. Fifteen days out
there is no plan behind it -- no queue item, no build, no price -- and the
release-candidate plan for *this* product reaches beyond it.

## Decision

**D27: the site says only what ships, in all six languages.**

- *"Everything Notepad does"* becomes *"it edits plain text the way Notepad
  does"* -- a claim about manner, not scope, and true.
- The two install claims become what the installation page's table says,
  with a link to that table: settings, recent files and the recovery journal
  live in the user profile, and removing the product is the folder plus those
  directories.
- `llms.txt`, which the build writes from `Build-Site.ps1` rather than from
  the locales, gets the same corrections.
- The installation page's two false sentences are fixed at the source, in
  `docs/user/`.

**D28: no date, and no countdown.** The waitlist page says BachelorPad+ is
*in development* and has no date yet, and that the waitlist hears first. The
countdown's markup, its script and its styles are removed, not hidden: a
countdown with nothing to count to is dead code on a page whose script is
meant to be small enough to read.

**The waitlist's feature list stays.** ADR-0076's argument for it holds: every
item is something that demonstrably worked in this repository before it was
removed. A feature list is a description; a date is a promise.

## Why no date, rather than a later one

A missed public date costs more than the countdown ever earned: every
release-candidate announcement would be made beside a promise already broken.
A later date would be the same promise with the same lack of a plan behind
it. When BachelorPad+ has a plan, the date comes from the plan.

## Consequences

**The translations need a native reader.** The French, German, Japanese and
Traditional Chinese strings were written by an agent, and the German locale
already had missing umlauts from an earlier pass. The corrected strings use
the right characters; the rest of `de-DE.json` still needs Daniel's review.

**A promise on a web page is trap 3**, which ADR-0076 said about trackers and
built a check for. The same check does not exist for claims about the
product, and cannot, in the form of a grep. What exists instead is this
table: the next person to write site copy has the three sentences that were
false and why.
