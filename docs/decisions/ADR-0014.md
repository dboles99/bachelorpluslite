# ADR-0014: Work Model and Traceability

**Status:** Accepted
**Date:** 2026-08-16

## Context

The project is built largely through AI coding agents working from reusable
prompt packets. That makes provenance -- which prompt produced which artefact
under which task -- worth capturing, and easy to lose if it is not captured
deliberately.

## Decision

Use the hierarchy:

```text
project -> task -> step -> prompts/rosettas -> artifacts -> metadata
        -> database -> note
```

Apply layers only where they add traceability. A task is a bounded objective
with explicit acceptance criteria; a step is a testable action.

## Consequences

- Not every task needs every layer, and forcing them produces ceremony rather
  than traceability.
- A task file without acceptance criteria is incomplete, because the layer
  that makes a task checkable is exactly the one it omitted.
- Generated artefacts record metadata (hash, source task, rosetta) so a file
  under `artifacts/` can be traced back to what produced it.
