# ADR-0039: Research Mode Turns Gathered Data Into Design Recommendations, Offline

**Status:** Proposed
**Date:** 2026-08-21

## Context

`bp-research` (5,208 lines, 161 tests) is the largest crate in this workspace
with zero reverse dependencies, and the roadmap has called it "the least
specified" of the three unreached modes since the phase existed. What it
already holds is entirely scholarly infrastructure: a bibliography model
(`Entry`, `Reference`), paper identifiers (`Doi`, `ArxivId`), citation-style
rendering (BibTeX, CSL) and a `ResearchProfile`. What phase 13 is *for* had no
answer to build any of that toward.

**The answer this ADR records does not obviously extend what is already
built.** Asked what research mode should do, the answer given was: develop
insights, options and recommendations from gathered data, to inform design,
features and function. That is product- and design-research language --
synthesising findings into recommendations -- and it sits at a real distance
from bibliography management. A literature review and a synthesis of user
research are both "research," but they are not the same feature, and nothing
forces `bp-research`'s existing citation model to be the foundation for the
second one. This ADR settles the *purpose*; whether the existing crate is the
right home for it, or whether phase 13 needs a data model this crate does not
have yet, is recorded as open rather than resolved by which crate happened to
be built first.

**One constraint was not open to interpretation.** `bp-research`'s own module
documentation states, deliberately: no HTTP client, no dependency that
implies one, and a test whose whole job is to notice if that changes.
ADR-0006 requires core editing to work without semantic or cloud features, and
`bp-research` currently satisfies that by being incapable of a network call at
all. Reaching a network from here needs an ADR that supersedes ADR-0006, and
the crate's own comment names that as a decision for "a human to write," not
one to arrive at as a side effect of scoping a mode.

## Decision

**Research mode synthesises data already present in the document or the
store; it does not fetch anything.** A user gathers material the way they
already can -- writing it into documents, citing sources `bp-research`
already models -- and research mode's job is to read what is there and
produce insights, named options and recommendations that speak to a design,
a feature, or a function under consideration. Nothing about this crosses the
network. Nothing here proposes reversing ADR-0006.

**Whether this rides on `bp-research` as it stands, or needs its own data
model built alongside it, is not decided here.** That is real design work --
what "gathered data" means concretely (documents already open? a folder the
user points at? `bp-storage`'s related-notes graph, once ADR-0037 is built?)
and what an "insight" or "recommendation" looks like on screen -- and it
belongs in its own pass rather than being defaulted into by whichever
existing crate is nearest.

**If synthesis implies generating prose from gathered material** -- writing
the insights and recommendations, not just retrieving and arranging them --
that is squarely the shape of work ADR-0033 was written for: a feature that
would want to reach a language model is exactly the kind ADR-0033 names
OpenAI's API as the vetted destination for, opt-in per use, never automatic.
Nothing in *this* ADR authorises that; it only notes that the two decisions
sit next to each other by design; ADR-0033 was answered the same session for
a reason.

## Consequences

- This does not fully close D-equivalent status the way the others did. It
  answers *purpose*, which is what was asked, but the open sub-question above
  -- bp-research as foundation, or a new data model -- needs its own decision
  before phase 13 can be scoped into buildable work. Status is **Proposed**
  rather than **Accepted** for exactly this reason, and it should be revisited
  once that sub-question has an answer, at which point this ADR is either
  confirmed as Accepted or superseded by the one that actually settles the
  foundation.
- `bp-research`'s offline guarantee, and its test that notices a network
  dependency arriving, are unchanged and unchallenged by this decision.
- If research mode's synthesis is meant to *generate* recommendations rather
  than surface and arrange gathered material, that is a feature under
  ADR-0033's network policy, opt-in, and a separate decision from this one --
  not something this ADR grants by implication.
- `project/NEXT_SESSION.md` and `project/WORK_QUEUE.md` can now describe
  phase 13 as "purpose decided, foundation not," rather than "the least
  specified" with nothing to react to.
